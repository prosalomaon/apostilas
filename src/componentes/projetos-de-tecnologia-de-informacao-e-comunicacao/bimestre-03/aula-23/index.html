Teoria & Conceitos: Tomada de Decisão e Fluxos de Repetição

Na aula anterior, estabelecemos a "ponte de ouro" entre as fórmulas de planilhas e os primeiros comandos em JavaScript, compreendendo variáveis, tipos de dados e condicionais simples. Nesta aula, daremos um passo fundamental no desenvolvimento do seu raciocínio lógico: aprenderemos a estruturar fluxos de decisão complexos, automatizar tarefas repetitivas por meio de estruturas de repetição (loops) e aplicar técnicas de otimização de algoritmos para garantir que seus scripts sejam claros, limpos e eficientes.

Para um profissional da área de negócios ou contabilidade, dominar essas estruturas permite criar rotinas automáticas de auditoria, processar lotes de milhares de lançamentos fiscais em milissegundos e simular cenários financeiros com alta performance.

1. O que é um Algoritmo sob a Ótica da Programação Estruturada?

Como aprendemos nos conceitos fundamentais, um algoritmo é um procedimento computacional bem definido que recebe um valor ou conjunto de valores como entrada (input) e produz um valor ou conjunto de valores como saída (output). Ele serve como uma ferramenta exata para resolver problemas passo a passo, sem margem para ambiguidades. Para que um programa resolva problemas do mundo real de maneira ótima, o fluxo de execução das instruções precisa ser controlado dinamicamente através de estruturas de controle.

2. Decisões Complexas: Estruturas Condicionais Avançadas (if, else if, else)

Nas planilhas, quando precisamos analisar mais de duas alternativas, recorremos ao aninhamento de funções SE (uma dentro da outra). No JavaScript, estruturamos essa mesma hierarquia lógica de forma muito mais limpa utilizando o encadeamento de if, else if (senão se) e else (senão):

  • if (Se): avalia se uma premissa inicial é verdadeira para executar o primeiro bloco de código.
  • else if (Senão se): adiciona novas condições intermediárias que só serão testadas caso a condição anterior seja falsa.
  • else (Senão): estabelece o caminho padrão que será executado se nenhuma das condições anteriores for atendida. 
// Exemplo de enquadramento tributário simplificado com if / else if / else
let faturamentoAnual = 380000;

if (faturamentoAnual <= 81000) {
    console.log("Enquadramento: MEI");
} else if (faturamentoAnual <= 360000) {
    console.log("Enquadramento: Microempresa (ME)");
} else if (faturamentoAnual <= 4800000) {
    console.log("Enquadramento: Empresa de Pequeno Porte (EPP)");
} else {
    console.log("Enquadramento: Lucro Presumido ou Real");
}

3. Estruturas de Repetição (Loops): for e while

Imagine que você precise auditar uma lista com 5.000 lançamentos contábeis. Escrever uma fórmula manual para cada linha seria inviável. É aqui que entram as estruturas de repetição (ou laços de repetição), permitindo que o computador execute o mesmo bloco de instruções várias vezes, iterando sobre coleções de dados:

  • O Loop for (Repetição com limite definido): é utilizado quando sabemos previamente o número exato de vezes que a repetição deve ocorrer. Ele se baseia em uma variável contadora, uma condição de parada e um incremento automático de controle.
    Sintaxe: for (inicialização; condição; incremento) { ... }
  • O Loop while (Repetição baseada em condição contínua): é executado enquanto uma determinada condição de teste for verdadeira. Ele é ideal quando não sabemos exatamente quantas iterações serão necessárias para atingir o objetivo.
    Sintaxe: while (condição) { ... }

4. Otimização de Algoritmos: Clareza e Eficiência

No desenvolvimento de softwares profissionais, otimizar significa projetar rotinas que realizem suas tarefas consumindo o mínimo de tempo de processamento e o mínimo de espaço em memória:

  • Eficiência (Complexidade de Tempo): algoritmos mal estruturados (como loops desnecessários uns dentro dos outros) podem fazer o computador ficar preso processando dados por minutos, enquanto um código otimizado resolveria a mesma tarefa em segundos.
  • Clareza (Legibilidade): um código legível, bem identado, com comentários pontuais e variáveis com nomes significativos é infinitamente mais fácil de auditar, testar e manter.

A Ponte Prática: Da Planilha ao Processamento em JavaScript

No Google Planilhas, quando queremos somar e analisar uma lista de transações mensais, criamos uma tabela e aplicamos funções matemáticas como a SOMA. No JavaScript, tratamos essa lista de dados como uma Matriz (Array), que é uma coleção ordenada de valores. Usamos o loop for para percorrer essa matriz do primeiro ao último item de forma automatizada.

Tabela de Dados Brutos (Transações Contábeis)

Para o nosso simulador, considere a seguinte lista de faturamentos mensais da empresa contábil de janeiro a maio:

Célula (Sheets) Mês Faturamento bruto (R$)
A2:B2 Jan 82000
A3:B3 Fev 85000
A4:B4 Mar 88000
A5:B5 Abr 91000
A6:B6 Mai 94000

Exemplo 1: Otimizando a Soma e Auditoria de Lançamentos com for

O script abaixo pega nossa matriz de faturamentos, calcula a soma total acumulada e avisa automaticamente caso algum mês apresente um faturamento atípico (acima de R$ 90.000): 

// 1. Declarando a matriz contendo o histórico de faturamentos
const faturamentos = [82000, 85000, 88000, 91000, 94000];
const meses = ["Jan", "Fev", "Mar", "Abr", "Mai"];

let faturamentoTotal = 0; // Variável acumuladora

console.log("--- INICIANDO AUDITORIA ANUAL ---");

// 2. Loop 'for' para percorrer a matriz de forma otimizada
for (let i = 0; i < faturamentos.length; i++) {
    let valorMensal = faturamentos[i];
    let mesCorrente = meses[i];

    // Acumula o valor mensal na soma total
    faturamentoTotal += valorMensal;

    // Condicional interna para auditoria de metas
    if (valorMensal > 90000) {
        console.log(`[ALERTA] ${mesCorrente}: Faturamento alto detectado (R$ ${valorMensal})`);
    }
}

// 3. Saída final de dados
console.log("---------------------------------");
console.log(`Soma Total do Período: R$ ${faturamentoTotal}`);

Resultado esperado ao executar:

--- INICIANDO AUDITORIA ANUAL ---
[ALERTA] Abr: Faturamento alto detectado (R$ 91000)
[ALERTA] Mai: Faturamento alto detectado (R$ 94000)
---------------------------------
Soma Total do Período: R$ 440000

Anatomia do Código

Parte do Código Equivalente na Planilha Significado
const faturamentos = [82000, ...] Intervalo de células B2:B6 Cria uma Matriz (Array), coleção ordenada de valores.
faturamentos.length Contagem de células preenchidas (CONT.NÚM) Propriedade que informa quantos itens existem na matriz.
faturamentos[i] Referenciar a célula da linha atual Acessa o item da posição i (a contagem começa em 0).
for (let i = 0; i < length; i++) Arrastar a fórmula para baixo até a última linha Inicializa o contador, testa a condição e incrementa a cada volta.
faturamentoTotal += valorMensal =SOMA(B2:B6) Operador de acúmulo: soma o valor mensal ao total acumulado.
`[ALERTA] ${mesCorrente}` Concatenação de texto com célula Template String: interpola variáveis dentro do texto usando crases e ${}.

Exemplo 2: Monitoramento Preventivo de Caixa com while

No planejamento financeiro corporativo, simular a queima de caixa e prevenir crises de liquidez é vital. O código abaixo simula um algoritmo de feedback que consome o saldo de caixa inicial para pagar custos operacionais mensais (OPEX), interrompendo o loop se o caixa atingir o limite crítico de segurança: 

let saldoCaixa = 120000;       // Caixa inicial
const opexMensal = 35000;      // Custo operacional fixo mensal
let mes = 1;

console.log("--- SIMULADOR DE LIQUIDEZ E SOBREVIVÊNCIA ---");
console.log(`Caixa Inicial: R$ ${saldoCaixa}`);

// O loop continuará rodando ENQUANTO houver saldo suficiente para pagar o custo mensal
while (saldoCaixa >= opexMensal) {
    saldoCaixa -= opexMensal; // Deduz o custo mensal do saldo acumulado
    console.log(`Mês ${mes} concluído. Saldo restante: R$ ${saldoCaixa}`);
    mes++;
}

// Quando o caixa fica menor que o custo fixo, o loop para
console.log("---------------------------------------------");
console.log(`[CRÍTICO] Falência de fluxo de caixa após o mês ${mes - 1}!`);
console.log(`Saldo de caixa final indisponível para OPEX: R$ ${saldoCaixa}`);

Resultado esperado ao executar:

--- SIMULADOR DE LIQUIDEZ E SOBREVIVÊNCIA ---
Caixa Inicial: R$ 120000
Mês 1 concluído. Saldo restante: R$ 85000
Mês 2 concluído. Saldo restante: R$ 50000
Mês 3 concluído. Saldo restante: R$ 15000
---------------------------------------------
[CRÍTICO] Falência de fluxo de caixa após o mês 3!
Saldo de caixa final indisponível para OPEX: R$ 15000

O Desafio Prático da Aula

Com base no conteúdo apresentado, monte o algoritmo de auditoria a seguir no seu ambiente de desenvolvimento (VS Code ou Console do Navegador).

Contexto do Desafio

Você recebeu uma lista com as margens de lucro líquido (%) de quatro projetos contábeis auditados:

Projeto Margem de Lucro Líquido (%)
Projeto Alfa 15%
Projeto Beta 8%
Projeto Gama -3% (Prejuízo)
Projeto Delta 22%

Sua Tarefa

  1. Crie uma matriz (Array) contendo as margens de lucro: const margens = [15, 8, -3, 22]; e outra com os nomes: const projetos = ["Alfa", "Beta", "Gama", "Delta"];
  2. Escreva um loop for que percorra as matrizes.
  3. Dentro do loop, insira uma estrutura condicional para avaliar a margem:
    • Se a margem for menor que 0, imprima: "[ALERTA] O Projeto [Nome] está dando prejuízo!"
    • Se for entre 0 e 10 (inclusive), imprima: "[ATENÇÃO] O Projeto [Nome] está com baixa lucratividade."
    • Se for maior que 10, imprima: "[OK] O Projeto [Nome] é altamente rentável."
  4. Certifique-se de que o código execute sem erros e que a saída de dados seja impressa de forma nítida.

Dicas, Lembretes & Boas Práticas

  • Identação é obrigatória para clareza: mantenha os blocos de código internos do if e do for sempre recuados com a tecla TAB. Isso permite visualizar instantaneamente onde cada comando começa e termina.
  • Cuidado com Loops Infinitos: no loop while, sempre certifique-se de que a variável de controle da condição mude de valor dentro do bloco (ex: mes++ ou saldoCaixa -= opexMensal). Caso contrário, a condição de parada nunca será atendida e o sistema travará a execução em loop infinito.
  • Otimize reduzindo processamento redundante: ao encadear condições, ordene-as de forma que as premissas mais prováveis ou excludentes venham primeiro. Isso economiza processamento computacional da CPU.
  • Comentários estruturados: documente as rotinas e funções do seu código para permitir que outros auditores ou desenvolvedores compreendam a regra de negócio que você implementou.

Como aplicar na Prática

Estruturas de decisão, repetição e otimização estão presentes nas rotinas tecnológicas do mundo real:

  • Rotinas automáticas de auditoria: escritórios de contabilidade usam loops para varrer milhares de lançamentos fiscais e sinalizar inconsistências automaticamente — exatamente como fizemos no Exemplo 1.
  • Análise de crédito e fluxo de caixa: simuladores de liquidez e "burn rate" de startups rodam loops while para projetar quantos meses a empresa sobrevive com o caixa atual.
  • Enquadramento tributário automatizado: sistemas de gestão fiscal classificam empresas (MEI, ME, EPP) encadeando condicionais sobre o faturamento anual.
  • Processamento em lote (batch): rotinas noturnas de bancos e ERPs processam lotes de transações com loops otimizados, onde cada segundo economizado representa economia real de recursos computacionais.
