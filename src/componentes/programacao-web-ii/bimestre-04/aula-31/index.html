Teoria & Conceitos

O gerenciamento de estado é um dos pilares da programação Web. Por natureza, o protocolo HTTP é stateless (sem estado), o que significa que o servidor trata cada requisição de forma isolada, sem uma memória nativa que reconheça se duas requisições consecutivas vieram do mesmo usuário.

Nesta aula, estudaremos como os Cookies atuam para resolver a ausência de estado do HTTP, permitindo armazenar preferências do usuário (como tema escuro/claro e idioma) e dados de histórico de navegação diretamente no navegador do cliente.

1.1. O Protocolo HTTP e a Necessidade do Estado

Como o servidor Web não guarda memória entre as navegações de páginas, dependemos de mecanismos de persistência externos para lembrar quem é o usuário e o que ele escolheu. Existem duas famílias de soluções:

  • Persistência no servidor: a aplicação grava os dados em disco ou banco de dados e mantém um identificador de referência no cliente. É o caso das sessões ($_SESSION), que serão estudadas em profundidade na próxima aula.
  • Persistência no cliente: o próprio navegador guarda os dados e os reenvia a cada requisição. É exatamente o caso dos cookies, objeto central do nosso estudo nesta aula.

Os cookies são pequenos arquivos de texto (ou coleções de dados chave/valor) armazenados pelo navegador a pedido do servidor Web. Sempre que o navegador solicita uma nova página para aquele mesmo domínio, ele inclui automaticamente os cookies armazenados nos cabeçalhos HTTP da requisição, no formato Cookie: nome=valor. 

GET /preferencias.php HTTP/1.1
Host: www.meusite.com.br
Cookie: preferencia_tema=escuro; idioma=pt-BR; historico_cursos=%5B%22Laravel%22%5D

1.2. Anatomia e Parâmetros de um Cookie

No PHP, a função nativa setcookie() envia o cabeçalho HTTP Set-Cookie ao navegador. Para garantir que um cookie funcione corretamente e com segurança, devemos conhecer seus parâmetros principais:

Parâmetro Descrição Exemplo
name Nome identificador do cookie. 'user_theme'
value Conteúdo gravado no cookie (até 4 KB de texto). 'dark'
expires Data/timestamp de expiração. Se for 0, expira ao fechar o navegador. time() + (86400 * 30)
path Caminho do servidor onde o cookie estará disponível (geralmente '/'). '/'
domain Domínio ou subdomínio autorizado a ler o cookie. '.meusite.com.br'
secure Se true, o cookie só é transmitido sob conexões criptografadas HTTPS. true
httponly Se true, o cookie fica inacessível para scripts client-side (JavaScript), mitigando ataques de XSS (Cross-Site Scripting). true
samesite Controla o envio cruzado de cookies para prevenir CSRF ('Lax', 'Strict', 'None'). 'Lax' 
<?php
// Sintaxe moderna (PHP 7.3+): array de opções, muito mais legível
setcookie('user_theme', 'dark', [
    'expires'  => time() + (86400 * 30), // 30 dias
    'path'     => '/',
    'domain'   => '.meusite.com.br',
    'secure'   => true,   // Exige HTTPS
    'httponly' => true,   // Bloqueia a leitura via JavaScript
    'samesite' => 'Lax'   // Mitiga CSRF
]);

1.3. Ciclo de Vida: Cookies de Sessão vs. Cookies Persistentes

A distinção entre os dois tipos de cookie é definida exclusivamente pelo parâmetro de expiração:

  • Cookie de Sessão: criado sem uma data de expiração explícita (ou com o valor 0). Ele reside apenas na memória RAM do navegador e é destruído assim que o usuário fecha o navegador.
  • Cookie Persistente: criado com um timestamp futuro definido no parâmetro expires (ex.: time() + 60*60*24*30 para 30 dias). Ele é gravado no disco rígido do cliente e sobrevive ao fechamento e reabertura do navegador.

1.4. Lendo Cookies: a Superglobal $_COOKIE

Quando o navegador reenvia os cookies na requisição, o PHP os disponibiliza automaticamente na superglobal $_COOKIE, um array associativo cujo índice é o nome do cookie e cujo valor é o conteúdo armazenado: 

<?php
// Leitura direta (pode gerar aviso se o cookie não existir)
$tema = $_COOKIE['preferencia_tema'];

// Leitura segura com operador de coalescência (evita o aviso de "Undefined index")
$tema = $_COOKIE['preferencia_tema'] ?? 'claro';

// Verificando a existência antes de usar
if (isset($_COOKIE['usuario_logado'])) {
    echo "Bem-vindo de volta!";
}

// Listando todos os cookies recebidos nesta requisição
foreach ($_COOKIE as $nome => $valor) {
    echo $nome . ' = ' . $valor;
}

1.5. Segurança e Boas Práticas com Cookies

Como os cookies ficam armazenados no computador do cliente, eles podem ser visualizados ou modificados pelo usuário a qualquer momento pelas ferramentas do navegador. Por isso, nunca armazene informações confidenciais (senhas, dados bancários ou regras de permissão) em cookies "limpos".

  1. Atraso de leitura na primeira carga: quando você executa setcookie() no PHP, o valor não fica disponível imediatamente no array $_COOKIE no mesmo script. O cookie só estará acessível na requisição seguinte, após o navegador recebê-lo e enviá-lo de volta. Por isso, finalizamos os exemplos com um header('Location: ...') seguido de exit;: assim forçamos um novo GET e a página já é montada com o cookie aplicado.
  2. Exclusão de cookies: para deletar um cookie existente, você deve chamá-lo novamente via setcookie() definindo uma data de expiração no passado (ex.: time() - 3600). O path precisa ser idêntico ao usado na criação, ou o navegador não reconhecerá o cookie como o mesmo.
  3. Proteção contra XSS e CSRF: ative as flags 'httponly' => true e 'samesite' => 'Lax' ou 'Strict' em todos os cookies que não precisem ser lidos por JavaScript.

Exemplos de Código

A seguir, três implementações completas usando a sintaxe moderna de opções do PHP 8. Todos os scripts seguem a mesma ordem obrigatória: processar o POST → gravar o cookie → redirecionar → ler o cookie → renderizar o HTML.

Exemplo 1: Gerenciador de Preferências de Tema (Claro / Escuro)

Este script verifica a preferência enviada pelo formulário, grava o cookie persistente por 30 dias e ajusta dinamicamente as classes do HTML. 

<?php
declare(strict_types=1);

// ==========================================
// 1. PROCESSAMENTO DO FORMULÁRIO
// ==========================================
if ($_SERVER['REQUEST_METHOD'] === 'POST' && isset($_POST['tema'])) {
    // Lista branca (allowlist): só aceitamos os valores previstos
    $temasValidos = ['claro', 'escuro'];

    if (in_array($_POST['tema'], $temasValidos, true)) {
        setcookie('preferencia_tema', $_POST['tema'], [
            'expires'  => time() + (86400 * 30), // Válido por 30 dias
            'path'     => '/',
            'secure'   => false, // Mudar para true em ambiente com HTTPS
            'httponly' => true,  // Proteção contra XSS
            'samesite' => 'Lax'  // Mitigação contra CSRF
        ]);

        // Redireciona (PRG Pattern) para recarregar a página já com o cookie aplicado
        header('Location: ' . $_SERVER['PHP_SELF']);
        exit;
    }
}

// ==========================================
// 2. LEITURA DA PREFERÊNCIA GRAVADA
// ==========================================
$temaAtual = $_COOKIE['preferencia_tema'] ?? 'claro';

// Escape obrigatório: o valor veio do navegador e pode ter sido adulterado
$temaAtualSanitizado = htmlspecialchars($temaAtual, ENT_QUOTES, 'UTF-8');
?>
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <title>Preferências de Interface</title>
</head>
<body class="tema-

Por que o redirecionamento é obrigatório aqui?

  • Evita o reenvio do formulário (padrão Post/Redirect/Get): se o usuário recarregar a página com F5, o navegador não repetirá o POST.
  • Solve o atraso de leitura: como o cookie só volta na requisição seguinte, o Location garante que a página exibida já leia $_COOKIE['preferencia_tema'] com o valor novo.
  • Se cair no PHP-FPM como página inicial, tudo funciona: o PHP não tem ligação com o Apache na porta 80; ele apenas escuta a porta 9000. O roteamento é feito inteiramente pela configuração do servidor Web.

Exemplo 2: Histórico de Cursos Recentemente Visitados

Abaixo criamos um sistema que registra os últimos cursos navegados pelo usuário, serializando um array em formato JSON dentro do cookie e mantendo no máximo 5 registros. 

<?php
declare(strict_types=1);

// Catálogo de cursos permitidos (evita injeção de qualquer texto na URL)
$cursosDisponiveis = [
    'PHP 8 Avançado',
    'Laravel Framework',
    'CSS Grid e Flexbox',
    'JavaScript ES6',
    'MySQL do Zero'
];

// ==========================================
// 1. HISTÓRICO: LER, ATUALIZAR E GRAVAR
// ==========================================
$historico = json_decode($_COOKIE['historico_cursos'] ?? '[]', true) ?: [];

// O parâmetro 'curso' só é aceito se existir no catálogo
$cursoAtual = $_GET['curso'] ?? null;

if ($cursoAtual !== null && in_array($cursoAtual, $cursosDisponiveis, true)) {
    // Remove duplicatas mantendo a ordem e reposiciona o curso acessado no topo
    $historico = array_values(array_unique(array_merge([$cursoAtual], $historico)));

    // Limita o histórico aos 5 itens mais recentes
    $historico = array_slice($historico, 0, 5);

    setcookie('historico_cursos', json_encode($historico), [
        'expires'  => time() + (86400 * 7), // 7 dias
        'path'     => '/',
        'httponly' => true,
        'samesite' => 'Lax'
    ]);
}
?>
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <meta charset="UTF-8">
    <title>Cursos</title>
</head>
<body>

    <?php if ($cursoAtual !== null && in_array($cursoAtual, $cursosDisponiveis, true)): ?>
        <h1>Você está visualizando o Curso: <?= htmlspecialchars($cursoAtual, ENT_QUOTES, 'UTF-8') ?></h1>
    <?php else: ?>
        <h1>Escolha um curso para começar</h1>
    <?php endif; ?>

    <h3>Navegar para outros cursos:</h3>
    <ul>
        <?php foreach ($cursosDisponiveis as $curso): ?>
            <li>
                <a href="?curso=<?= urlencode($curso) ?>">
                    <?= htmlspecialchars($curso, ENT_QUOTES, 'UTF-8') ?>
                </a>
            </li>
        <?php endforeach; ?>
    </ul>

    <hr>

    <h3>Seu Histórico de Navegação Recente (Últimos 5):</h3>
    <?php if (empty($historico)): ?>
        <p><em>Nenhum curso acessado ainda. Navegue pela lista acima para popular seu histórico.</em></p>
    <?php else: ?>
        <ol>
            <?php foreach ($historico as $item): ?>
                <li><?= htmlspecialchars($item, ENT_QUOTES, 'UTF-8') ?></li>
            <?php endforeach; ?>
        </ol>
    <?php endif; ?>

</body>
</html>

Exemplo 3: Destruindo e Limpando Cookies de Preferência

Demonstração de como redefinir as preferências do usuário removendo os cookies ativos por meio de uma data de expiração no passado. 

<?php
declare(strict_types=1);

if ($_SERVER['REQUEST_METHOD'] === 'POST' && isset($_POST['limpar'])) {
    // O 'path' precisa ser IDÊNTICO ao usado na criação do cookie
    setcookie('preferencia_tema', '', [
        'expires'  => time() - 3600,
        'path'     => '/'
    ]);

    setcookie('historico_cursos', '', [
        'expires'  => time() - 3600,
        'path'     => '/'
    ]);

    header('Location: ' . $_SERVER['PHP_SELF']);
    exit;
}
?>

Dicas, Lembretes e Segurança (LGPD)

  • Headers already sent: a função setcookie() modifica os cabeçalhos HTTP e deve ser chamada antes de qualquer saída HTML, espaço em branco ou instrução echo. Caso contrário, o PHP emitirá o aviso Cannot modify header information - headers already sent.
  • Proteção contra XSS na saída: ao recuperar dados de $_COOKIE para renderizá-los na página, aplique sempre htmlspecialchars() para neutralizar códigos JavaScript maliciosos que o usuário possa ter injetado manualmente no navegador.
  • Lei Geral de Proteção de Dados (LGPD): o uso de cookies para rastreamento de comportamento e histórico exige transparência. Apresente ao usuário uma política de privacidade e obtenha consentimento ativo para cookies não essenciais.
  • Limites do navegador: cada domínio pode armazenar uma média de 20 a 50 cookies, e a soma do tamanho de todos eles não pode ultrapassar 4 KB (4096 bytes). Para volumes maiores de dados no cliente, utilize localStorage do JavaScript ou salve as informações em banco de dados vinculadas à sessão do usuário ($_SESSION).

Como aplicar na Prática

  • Tema claro/escuro: grave a preferência com setcookie() por 30 dias, aplique httponly => true e samesite => 'Lax', e renderize o valor com htmlspecialchars() no atributo class do body.
  • Histórico de navegação: serialize um array com json_encode(), deserialize com json_decode($valor, true) e sempre limite o tamanho com array_slice() para respeitar o limite de 4 KB do cookie.
  • Idioma e moeda preferidas: use cookies persistentes de longa duração (time() + 60*60*24*365) para lembrar escolhas de longo prazo do usuário.
  • Botão "limpar preferências": revogue os cookies gravando-os novamente com expires => time() - 3600 e o mesmo path, requisito essencial para atender ao direito de descarte previsto na LGPD.
  • Cookie de sessão PHPSESSID: quando você chamar session_start(), o PHP cria automaticamente um cookie desse tipo. Ele é o elo de ligação entre o navegador e os dados da sessão guardados no servidor — assunto da aula 32.
