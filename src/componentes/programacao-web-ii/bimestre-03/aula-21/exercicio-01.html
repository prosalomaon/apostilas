Enunciado

Você foi contratado(a) para estruturar o banco de dados de um portal Web. Em vez de escrever o código PHP diretamente, o objetivo desta atividade é exercitar os três subconjuntos da linguagem SQL vistos na aula: DDL (definição), DML (manipulação) e DQL (consulta).

Execute cada bloco no seu servidor MySQL e valide os resultados com consultas antes de prosseguir.

Preparação

  1. Ambiente: Abra seu terminal ou o MySQL Workbench e conecte-se ao seu servidor local.
  2. Script: Execute o script da seção "1. Script de Preparação" integralmente e confirme que o banco portal_db foi criado.
  3. Resolução: Escreva cada comando manualmente (não copie tudo de uma vez) para internalizar a sintaxe de cada subconjunto.
  4. Validação: Após cada bloco, execute o SELECT de conferência indicado e compare com o resultado esperado.

1. Script de Preparação (MySQL)

Execute o script abaixo para criar o banco e a tabela usuarios do portal:

CREATE DATABASE portal_db;
USE portal_db;

CREATE TABLE usuarios (
    id INT NOT NULL AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) UNIQUE,
    senha VARCHAR(255) NOT NULL,
    data_cadastro DATE NOT NULL,
    PRIMARY KEY (id)
);

INSERT INTO usuarios (nome, email, senha, data_cadastro) VALUES
('Ana Silva', 'ana@gmail.com', 'hash_123', '2026-02-10'),
('Bruno Costa', 'bruno@gmail.com', 'hash_456', '2026-03-05'),
('Carla Souza', 'carla@hotmail.com', 'hash_789', '2026-04-18'),
('Diego Lima', 'diego@gmail.com', 'hash_321', '2026-05-02');

2. Desafios de Prática

Bloco 1: DDL – Definição de Estrutura

  1. Execute DESCRIBE usuarios; e anote os tipos de cada coluna.
  2. Use ALTER TABLE para adicionar a coluna telefone VARCHAR(20) à tabela.
  3. Use ALTER TABLE para adicionar a coluna ativo TINYINT NOT NULL DEFAULT 1.
  4. Confirme a nova estrutura com DESCRIBE usuarios;.

Bloco 2: DML – Inserção, Atualização e Remoção

  1. Insira um novo usuário com INSERT INTO: 
    INSERT INTO usuarios (nome, email, senha, data_cadastro) VALUES
('Erika Rocha', 'erika@gmail.com', 'hash_654', '2026-06-01');
  2. Atualize o telefone do usuário "Ana Silva" usando UPDATE ... WHERE: 
    UPDATE usuarios SET telefone = '(11) 99999-0000' WHERE nome = 'Ana Silva';
  3. Remova o usuário "Carla Souza" com DELETE ... WHERE id = 3.
  4. Confira com: 
    SELECT id, nome, email FROM usuarios;
    Resultado esperado: 4 registros (Carla Souza deve ter sido removida).

Bloco 3: DQL – Consultas Filtradas e Ordenadas

  1. Liste apenas nome e email dos usuários com e-mail @gmail.com, ordenados por nome em ordem alfabética: 
    SELECT nome, email FROM usuarios WHERE email LIKE '%@gmail.com' ORDER BY nome ASC;
  2. Liste os usuários cadastrados após '2026-03-01', do mais recente para o mais antigo (ORDER BY data_cadastro DESC).
  3. Conte quantos usuários possuem e-mail do Gmail usando COUNT(*) com LIKE '%@gmail.com'.

Bloco 4: Refletindo sobre a Prática

  1. Explique, com suas palavras, em qual fase de um projeto Web cada subconjunto é mais utilizado: DDL, DML e DQL.
  2. Por que AUTO_INCREMENT na chave primária facilita o trabalho da aplicação Web ao cadastrar novos usuários?
  3. O que aconteceria se o comando DELETE FROM usuarios fosse executado sem a cláusula WHERE? O que isso ensina sobre a escrita de comandos DML?

Orientações Finais

  • WHERE é obrigatório em UPDATE/DELETE: sem ele, todos os registros são afetados. No PHP, isso significa sempre filtrar por id ou outro campo único.
  • Conferência: depois de cada comando DML, execute um SELECT para confirmar o efeito esperado.
  • Dicionário de dados: documente tamanho e regras de cada coluna — isso guiará as validações do PHP na aula seguinte.
  • Tente sozinho: escreva os comandos de memória; volte à aula apenas se travar em algum conceito.
