Enunciado

Você foi contratado(a) para desenvolver o back-end de um pequeno sistema de biblioteca. O objetivo desta atividade é construir, passo a passo, uma camada de acesso a dados segura usando a classe PDO — do estabelecimento da conexão até as operações de CRUD e uma transação, aplicando prepare() + execute() em todas as consultas.

Execute e valide cada etapa no seu ambiente com PHP 8 e MySQL antes de prosseguir para a próxima.

Preparação

  1. Ambiente: garanta PHP 8+ com a extensão pdo_mysql habilitada (php -m) e um servidor MySQL local.
  2. Banco: execute o script da seção "1. Preparação do Banco" para criar o banco e a tabela livros.
  3. Organização: crie os arquivos conforme indicado, mantendo as credenciais em um arquivo separado (fora do diretório público, idealmente).
  4. Validação: após cada bloco, rode o código e confirme a saída esperada no navegador.

1. Preparação do Banco (MySQL)

Crie o banco e a tabela que serão usados na atividade:

CREATE DATABASE biblioteca;
USE biblioteca;

CREATE TABLE livros (
    id INT NOT NULL AUTO_INCREMENT,
    titulo VARCHAR(200) NOT NULL,
    isbn VARCHAR(20) UNIQUE,
    ano_publicacao INT,
    PRIMARY KEY (id)
);

INSERT INTO livros (titulo, isbn, ano_publicacao) VALUES
('Introdução ao PHP 8', '9781111111111', 2022),
('Banco de Dados com MySQL', '9782222222222', 2023);

2. Estrutura de Arquivos Proposta

  • conexao.php — abre a conexão segura com o PDO (reutilizado por todos os blocos).
  • create.php — insere um novo livro (Exemplo 2 da aula).
  • read.php — busca livros por título (Exemplo 3 da aula).
  • update_delete.php — altera e remove registros (Exemplo 4 da aula).
  • transacao.php — realiza uma transferência atômica (Exemplo 5 da aula).

3. Desafios de Prática

Bloco 1: Conexão Segura (conexao.php)

  1. Crie o arquivo conexao.php com as credenciais e a instância do PDO, usando try...catch, ERRMODE_EXCEPTION, FETCH_ASSOC e EMULATE_PREPARES => false: 
    <?php
// conexao.php - reutilize este arquivo em todos os blocos (require_once 'conexao.php')
define('DB_HOST', 'localhost');
define('DB_NAME', 'biblioteca');
define('DB_USER', 'root');
define('DB_PASS', 'SUA_SENHA');

try {
    $dsn = "mysql:host=" . DB_HOST . ";dbname=" . DB_NAME . ";charset=utf8mb4";
    $pdo = new PDO($dsn, DB_USER, DB_PASS, [
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES   => false
    ]);
} catch (PDOException $e) {
    error_log("Falha de conexão: " . $e->getMessage());
    die("Falha de comunicação. Tente novamente.");
}
  2. Responda e valide: altere a $dsn para apontar para outro driver (ex.: sqlite). O que precisa mudar? O que permanece igual? Confirme que a portabilidade do PDO é real.

Bloco 2: CREATE Seguro (create.php)

  1. Com require_once 'conexao.php';, insira um novo livro usando placeholders nomeados (:titulo, :isbn, :ano) e exiba o $pdo->lastInsertId(): 
    <?php
require_once 'conexao.php';

$sql = "INSERT INTO livros (titulo, isbn, ano_publicacao)
        VALUES (:titulo, :isbn, :ano)";
$stmt = $pdo->prepare($sql);
$stmt->execute([
    ':titulo' => 'Descomplicando APIs REST',
    ':isbn'   => '9783333333333',
    ':ano'    => 2024
]);
echo "Novo ID gerado: " . $pdo->lastInsertId();
  2. Tente inserir um livro com ISBN duplicado. O que acontece? Isso é uma falha ou uma proteção do banco?

Bloco 3: READ Seguro (read.php)

  1. Busque livros cujo título contenha o termo "PHP" usando placeholder posicional (?) e exiba os resultados com htmlspecialchars(): 
    <?php
require_once 'conexao.php';

$busca = "%PHP%";
$stmt = $pdo->prepare("SELECT id, titulo, isbn, ano_publicacao FROM livros WHERE titulo LIKE ?");
$stmt->execute([$busca]);

foreach ($stmt->fetchAll() as $livro) {
    echo htmlspecialchars($livro['titulo'], ENT_QUOTES, 'UTF-8')
       . " | " . htmlspecialchars($livro['isbn'], ENT_QUOTES, 'UTF-8')
       . " | " . $livro['ano_publicacao'] . "<br>";
}
  2. Explique por que o retorno do banco precisa passar por htmlspecialchars().

Bloco 4: UPDATE e DELETE (update_delete.php)

  1. Altere o título e remova um registro, verificando o impacto com rowCount(): 
    <?php
require_once 'conexao.php';

$stmtUpdate = $pdo->prepare("UPDATE livros SET titulo = :titulo WHERE id = :id");
$stmtUpdate->execute([':titulo' => 'Descomplicando APIs REST (2ª ed.)', ':id' => 3]);
echo "Linhas alteradas: " . $stmtUpdate->rowCount() . "<br>";

$stmtDelete = $pdo->prepare("DELETE FROM livros WHERE id = ?");
$stmtDelete->execute([4]);
echo "Linhas removidas: " . $stmtDelete->rowCount();
  2. O que rowCount() retorna quando o WHERE não encontra nenhum registro? Teste para confirmar.

Bloco 5: Transação Atômica (transacao.php)

  1. Simule uma transferência entre duas contas usando beginTransaction(), commit() e rollBack(): 
    <?php
require_once 'conexao.php';

// Preparação: crie antes a tabela contas:
// CREATE TABLE contas (id INT PRIMARY KEY, saldo DECIMAL(10,2));
// INSERT INTO contas VALUES (1, 1000.00), (2, 1000.00);

try {
    $pdo->beginTransaction();

    $debito = $pdo->prepare("UPDATE contas SET saldo = saldo - :v WHERE id = :c");
    $debito->execute([':v' => 500.00, ':c' => 1]);

    $credito = $pdo->prepare("UPDATE contas SET saldo = saldo + :v WHERE id = :c");
    $credito->execute([':v' => 500.00, ':c' => 2]);

    $pdo->commit();
    echo "Transferência realizada com sucesso!";
} catch (Exception $e) {
    $pdo->rollBack();
    error_log("Transação cancelada: " . $e->getMessage());
    echo "Erro: nenhuma movimentação foi efetuada.";
}
  2. Modifique o valor do débito para exceder o saldo da conta 1 e simule uma falha. A conta 2 continua recebendo o crédito? Explique o papel do rollBack().

Orientações Finais

  • Prepared statements em tudo: nunca concatene valores vindos do usuário na string SQL — sempre prepare() + execute().
  • Proteja a saída: ao exibir dados do banco, use htmlspecialchars() para evitar XSS.
  • Não exponha credenciais: mantenha host, banco, usuário e senha fora do diretório público da aplicação.
  • Menor privilégio: use um usuário de banco específico (não root) com apenas SELECT, INSERT, UPDATE, DELETE.
