Enunciado

O sistema da Livraria do Saber precisa documentar o cenário "Efetuar Login". A equipe de projeto deve produzir um Diagrama de Sequência que represente com precisão as regras de autenticação, usando os operadores de controle da UML 2.0.

Parte 1 – Construir o Diagrama de Sequência

Desenhe (à mão ou com ferramenta) o Diagrama de Sequência do cenário abaixo, usando os Fragmentos Combinados:

  1. O ator Usuário envia autenticar(usuário, senha) para o objeto sistema : Sistema.
  2. Operador alt:
    • [senha válida]: o sistema envia criarSessão() a sessão : Sessão e retorna "Acesso liberado".
    • [else]: o sistema incrementa as tentativas e retorna "Senha inválida".
  3. Após o alt, um operador opt: se [usuário é administrador], o sistema executa a auto-chamada registrarAuditoriaAdmin().
  4. Um operador loop com limites loop(0, 3): enquanto a senha for inválida e ainda houver tentativas, o sistema solicita nova senha ao usuário.
  5. Um operador break [tentativas esgotadas]: o sistema bloqueia a conta (bloquearConta()) e o restante do diagrama é ignorado.
  6. Ao final, se não houve interrupção, o sistema envia mensagem de boas-vindas ao usuário.

Parte 2 – Escolha o operador adequado

Para cada situação abaixo, indique qual operador (alt, opt, loop, par, break, ref) é o mais adequado e justifique:

  1. Uma interação de autenticação reutilizada em vários cenários do sistema.
  2. Executar simultaneamente a gravação do log e o envio do e-mail de confirmação.
  3. Aplicar um desconto apenas se o cliente for VIP.
  4. Percorrer todos os itens de uma lista para calcular o total.
  5. Escolher entre [estoque disponível] reservar o item ou [else] informar indisponibilidade.
  6. Encerrar o processamento antes da confirmação quando o pagamento é negado.

Parte 3 – Análise e melhoria

  1. Identifique no seu diagrama as guardas e os operandos de cada fragmento.
  2. Justifique por que, no bloco alt da Parte 1, foi usado [else] como sentinela.
  3. Explique por que o operador loop(0, 3) limita as tentativas mesmo que a guarda ainda seja verdadeira.

Orientações

  • Releia a aula antes de começar; a tabela dos operadores principais ajuda na escolha correta.
  • Não use quadros de interação em excesso: represente apenas a lógica crucial do fluxo.
  • Use a guarda [else] nos blocos alt para manter o modelo bem-formado.
  • Confira se as mensagens dentro de cada fragmento estão na ordem correta e se as linhas de vida estão conectadas.
  • Para representar ref, basta indicar o nome do diagrama referenciado dentro de um quadro com a tag ref.
