Enunciado

O banco TechBank desenvolveu o trecho de código Java abaixo para o cenário "Abertura de Conta". Sua tarefa é transformar esse código em um Diagrama de Sequência UML, utilizando todos os conceitos estudados na aula.

Parte 1 – O Código Java

// Ponto de entrada: chamado pelo ator (gerente)
public void abrirConta(String cpf, double depositoInicial) {
    // 1. Criação do objeto cliente (estereótipo <<create>>)
    Cliente cliente = new Cliente(cpf);

    // 2. Criação do objeto conta (estereótipo <<create>>)
    Conta conta = new Conta(cliente);

    // 3. Chamada síncrona com retorno (reply)
    double saldo = conta.calcularSaldoInicial(depositoInicial);

    // 4. Auto-chamada (self-message) para validar as regras da agência
    this.validarLimites(saldo);

    // 5. Chamada assíncrona: dispara e segue sem esperar resposta
    this.notificarSMS.concluido("Conta aberta com sucesso");

    // 6. Retorno ao ator
    System.out.println("Conta " + conta.getNumero() + " aberta");
}

public double calcularSaldoInicial(double depositoInicial) {
    double bonus = this.agencia.calcularBonus();   // chamada síncrona a outro objeto
    return depositoInicial + bonus;                // retorna o saldo (mensagem de retorno)
}

public void validarLimites(double saldo) {
    if (saldo > 10000) {
        this.agencia.liberarAltaPremium();          // chamada síncrona
    }
}

Classes envolvidas: o sistema umSistema : Sistema (que executa o método abrirConta()), umCliente : Cliente, umaConta : Conta, a agencia : Agencia (que concentra as regras de negócio, como calcularBonus() e liberarAltaPremium()) e o serviço externo notificarSMS : SmsSender.

Parte 2 – Construção do Diagrama

Desenhe (à mão ou com ferramenta de modelagem) o Diagrama de Sequência correspondente ao código, na ordem de ocorrência, incluindo:

  • O ator Gerente e os objetos participantes.
  • As linhas de vida e os focos de controle (ativações).
  • As mensagens de criação dos objetos Cliente e Conta, com o estereótipo <<create>>.
  • A mensagem síncrona calcularSaldoInicial() e a respectiva mensagem de retorno (reply).
  • A auto-chamada validarLimites().
  • A mensagem assíncrona para o serviço externo de SMS.

Roteiro guiado para conferir o diagrama

Etapa Elemento no diagrama Base no código
1 Ator Gerente → Agencia (síncrona abrirConta()) public void abrirConta(...)
2 Criação <<create>> de umCliente : Cliente new Cliente(cpf)
3 Criação <<create>> de umaConta : Conta new Conta(cliente)
4 Síncrona calcularSaldoInicial() + retorno saldo double saldo = conta.calcularSaldoInicial(...)
5 Síncrona calcularBonus() em agencia this.agencia.calcularBonus()
6 Auto-chamada validarLimites() (foco em Agencia) this.validarLimites(saldo)
7 Síncrona condicional liberarAltaPremium() (se saldo > 10000) if (saldo > 10000) { ... }
8 Assíncrona concluido(texto) para SmsSender this.notificarSMS.concluido(...)
9 Retorno final ao ator Gerente System.out.println(...)

Parte 3 – Questões

Questão 1: Participantes e Linhas de Vida

Liste todos os participantes do diagrama (ator e objetos). Para cada objeto, escreva o nome no formato nomeObjeto : NomeClasse e explique o que a linha da vida representa nesse cenário.

Questão 2: Focos de Controle

Indique em quais trechos do diagrama cada objeto entra em foco de controle (ativação). Explique por que o objeto umaConta : Conta entra e sai de ativação mais de uma vez.

Questão 3: Mensagens Síncronas e de Retorno

Identifique as mensagens síncronas do diagrama e, para cada uma, descreva a correspondente mensagem de retorno (reply). Explique o que acontece com o chamador (ex: o objeto Agencia) durante uma chamada síncrona ao Conta.

Questão 4: Mensagem Assíncrona

Explique por que a mensagem concluido() para o serviço de SMS é assíncrona e qual é a diferença de comportamento do chamador em relação a uma chamada síncrona.

Questão 5: Auto-chamada e Criação

Descreva a auto-chamada validarLimites() apresentada no roteiro. Em seguida, explique como as mensagens de criação (<<create>>) são representadas e por que a linha da vida de um objeto criado tem início no momento em que recebe a seta de criação.

Questão 6: Condição no Diagrama

O código contém um if (saldo > 10000). Em um Diagrama de Sequência, como você representaria essa lógica condicional (ex: fragmento alt/ opt)? Descreva como ficaria o fragmento para a chamada liberarAltaPremium().

Questão 7: Destruição

No código fornecido nenhum objeto é explicitamente destruído. Explique quando e como o recurso de destruição (marcado com um X no final da linha da vida) seria aplicado em um cenário como este, e em qual participantes poderia ser usado.

Orientações

  • Releia o conteúdo da aula antes de começar; a tabela de elementos fundamentais ajuda na construção.
  • Organize as mensagens de cima para baixo, respeitando a ordem de execução do código.
  • Use a sintaxe nomeObjeto : NomeClasse para nomear os objetos.
  • Cada chamada de método vira uma seta; cada return vira uma mensagem de retorno.
  • Lembre-se: síncrona = seta de ponta preenchida; assíncrona = seta de ponta aberta; retorno = seta tracejada de ponta aberta; criação = seta com <<create>>; destruição = X no fim da linha da vida.
  • Não polua o diagrama: mostre apenas as chamadas cruciais para entender a lógica do design.
