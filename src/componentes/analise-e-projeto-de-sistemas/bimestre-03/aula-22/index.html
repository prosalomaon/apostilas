Teoria & Conceitos

1. Visão Geral e Propósito

O Diagrama de Sequência é um diagrama de interação que enfatiza a ordenação temporal das mensagens trocadas entre os objetos. Ele descreve como os objetos colaboram em um cenário específico de um Caso de Uso, mostrando o fluxo de controle e a comunicação ao longo do tempo.

  • Objetivo: capturar o comportamento dinâmico, detalhando "quem faz o quê e em qual ordem" para realizar uma funcionalidade.
  • Perspectiva: oferece uma visão holística do comportamento, focando nos papéis desempenhados pelos participantes na interação.

2. Elementos Fundamentais

  • Participantes (Atores e Objetos): são dispostos horizontalmente no topo do diagrama.
    • Atores: representam papéis externos que iniciam a interação.
    • Objetos: instâncias das classes. A sintaxe comum é nomeObjeto : NomeClasse (ex: umPedido : Pedido).
  • Linha da Vida (Lifeline): uma linha tracejada vertical que desce de cada participante, representando sua existência durante a interação.
  • Foco de Controle / Ativação (Execution Specification): um retângulo fino e vertical sobreposto à linha da vida. Indica o período em que um objeto está executando uma operação ou esperando o retorno de uma chamada.

3. Mensagens e Comunicação

As mensagens são representadas por setas horizontais que ligam as linhas de vida dos participantes, organizadas de cima para baixo conforme a ordem de ocorrência.

A. Mensagem Síncrona

Representada por uma seta com ponta preenchida. O chamador para sua execução e espera que o receptor processe a mensagem antes de continuar.

B. Mensagem Assíncrona

Representada por uma seta com ponta aberta ("pé de galinha"). O chamador envia a mensagem e continua seu processamento sem esperar resposta.

C. Mensagem de Retorno (Reply)

Uma seta tracejada com ponta aberta, usada para indicar a devolução de informação ao chamador após uma mensagem síncrona. Frequentemente é omitida se o retorno for óbvio, para evitar poluir o diagrama.

D. Criação e Destruição

  • Criação: uma seta de mensagem apontando diretamente para o retângulo de um novo objeto, com o estereótipo <<create>>.
  • Destruição: marcada por um X grande no final da linha da vida, indicando que o objeto deixou de existir ou que a sessão foi encerrada.

Exemplo Prático: Cálculo de Preço de um Pedido

Considere o cenário "Calcular Preço" de um pedido com base em suas linhas de item. Os participantes são um ator externo, o objeto umPedido : Pedido, suas linhas (umaLinhaDePedido : LinhaDePedido) e o umCliente : Cliente:

  1. O ator envia a mensagem síncrona calcularPreço() para umPedido.
  2. umPedido entra em foco de controle. Ele percorre seus itens, enviando obterQuantidade() e obterProduto() para cada umaLinhaDePedido.
  3. umaLinhaDePedido devolve as informações (mensagens de retorno).
  4. umPedido realiza uma auto-chamada (mensagem enviada para si mesmo) chamada calcularPreçoBase() para consolidar os valores.
  5. Por fim, umPedido envia obterInformaçãoDeDesconto() para umCliente para aplicar a regra final antes de retornar o preço total ao ator.
sequenceDiagram actor Usuario participant umPedido as umPedido : Pedido participant linha as umaLinhaDePedido : LinhaDePedido participant umCliente as umCliente : Cliente Usuario->>umPedido: calcularPreço() activate umPedido loop para cada linha do pedido umPedido->>linha: obterQuantidade() linha-->>umPedido: quantidade umPedido->>linha: obterProduto() linha-->>umPedido: produto end umPedido->>umPedido: calcularPreçoBase() umPedido->>umCliente: obterInformaçãoDeDesconto() umCliente-->>umPedido: desconto umPedido-->>Usuario: preço total deactivate umPedido

O mesmo cenário traduzido para código: cada seta do diagrama corresponde a uma chamada de método, e o foco de controle corresponde ao bloco de execução do método chamado. 

// Ator envia a mensagem síncrona calcularPreco()
double preco = umPedido.calcularPreco();

// Método executado por umPedido (foco de controle)
public double calcularPreco() {
    double total = 0;
    for (LinhaDePedido linha : this.linhas) {          // percorre cada linha
        int qtd = linha.obterQuantidade();             // seta -> quantidade (retorno)
        Produto produto = linha.obterProduto();        // seta -> produto (retorno)
        total += qtd * produto.getPreco();
    }
    total = this.calcularPrecoBase(total);             // auto-chamada
    double desconto = this.cliente.obterInformacaoDeDesconto(total);
    return total - desconto;                           // retorno ao ator
}

Em código, a linha da vida de umItem fica ativa apenas durante a chamada consultar(); a auto-chamada processar() mantém ativo apenas o foco do próprio umPedido. 

DadosItem dados = umItem.consultar();   // chamada síncrona -> foco em umItem
umPedido.processar(dados);              // auto-chamada   -> foco apenas em umPedido

public void processar(DadosItem dados) {
    this.estado = Estado.PROCESSADO;    // instruções executadas sob o foco de controle
}

Síncrona vs. Assíncrona vs. Retorno

sequenceDiagram participant A as Chamador participant B as Receptor participant C as ServiçoExterno A->>B: mensagem síncrona() activate B B-->>A: retorno síncrono deactivate B A--)C: mensagem assíncrona() A->>B: criarTrabalho()

Na chamada síncrona, o chamador aguarda o retorno; na assíncrona, ele dispara a mensagem e segue seu fluxo imediatamente: 

// Síncrona: o chamador espera o processamento e recebe a resposta (reply)
Resposta resposta = receptor.mensagemSincrona();

// Assíncrona: o chamador envia e continua sem esperar resposta
executor.submit(() -> servicoExterno.mensagemAssincrona());

// Fluxo do chamador prossegue imediatamente, sem bloquear
receptor.criarTrabalho();

Criação e destruição de objetos

A criação é representada por uma seta que aponta diretamente para o retângulo do novo objeto (estereótipo <<create>>); a destruição, por um X no final da linha da vida.

sequenceDiagram participant App as Aplicação participant S as Sessão App->>S: criarSessão() activate S App->>S: autenticar(usuario, senha) S-->>App: token App->>S: encerrar() deactivate S destroy S 
// Criação (estereótipo <<create>>): seta apontando para o novo objeto
Sessao sessao = new Sessao();

// Mensagem síncrona com retorno (reply)
Token token = sessao.autenticar(usuario, senha);

// Encerramento da sessão
sessao.encerrar();

// Destruição (X no fim da linha da vida): o objeto deixa de existir
sessao = null;

Dicas & Lembretes

  • Sequência vs. Comunicação: enquanto o Diagrama de Sequência foca no tempo, o Diagrama de Comunicação foca nos vínculos (links) entre os objetos.
  • Seletividade: não tente mostrar cada detalhe do código. Foque nas chamadas entre participantes que são cruciais para entender a lógica do design.
  • Lógica de Controle: diagramas de sequência são ótimos para visualizar interações, mas não são ideais para algoritmos complexos com muitos laços e condições; para esses casos, prefira o código ou os Diagramas de Atividades.
  • Retornos implícitos: quando a devolução é óbvia, omita a seta de retorno para manter o diagrama limpo.
  • Nomes de objeto: use a sintaxe nomeObjeto : NomeClasse para deixar claro qual instância participa.

Como aplicar na Prática

  • Do caso de uso ao design: para cada cenário principal do Caso de Uso, crie um Diagrama de Sequência que mostre a colaboração entre as classes de projeto para realizar a funcionalidade.
  • Validação de lógica: use o diagrama para verificar se as mensagens estão na ordem correta e se todos os retornos de dados necessários estão contemplados antes da implementação.
  • Comunicação com a equipe: apresente o diagrama nas reuniões de design para alinhar o fluxo da interação entre desenvolvedores, evitando implementações divergentes.
  • Modelagem de integrações: use mensagens assíncronas para representar envios de eventos, filas e notificações, e síncronas para chamadas de serviços que exigem resposta imediata.
