Objetivo

Analisar a implementação em Java do módulo de pedidos de um totem de fast-food e construir os seguintes artefatos UML:

  • Diagrama de Casos de Uso (visão funcional/comportamental);
  • Diagrama de Classes (visão estrutural).

Entrega

Com base na análise do código-fonte abaixo, construa diretamente os dois diagramas UML e entregue-os:

  1. Diagrama de Casos de Uso — identificando os atores (principal e sistemas externos), os casos de uso derivados do código e os relacionamentos aplicáveis (incluindo <<include>> e <<extend>>).
  2. Diagrama de Classes — com nome, atributos e métodos (visibilidade correta: - para private, + para public) e os relacionamentos com suas multiplicidades.

Para consultar exemplos de representação gráfica, revise as aulas 12 e 13 (Diagrama de Casos de Uso) e as aulas 15 a 17 (Diagrama de Classes).

Código-Fonte Java Base

Use o código abaixo como base para a análise:

import java.util.ArrayList;
import java.util.List;

// --- CLASSE PRODUTO ---
public class Produto {
    private String codigo;
    private String nome;
    private double preco;

    public Produto(String codigo, String nome, double preco) {
        this.codigo = codigo;
        this.nome = nome;
        this.preco = preco;
    }

    public double getPreco() {
        return preco;
    }

    public String getNome() {
        return nome;
    }
}

// --- CLASSE ITEM PEDIDO ---
public class ItemPedido {
    private int quantidade;
    private Produto produto;

    public ItemPedido(Produto produto, int quantidade) {
        this.produto = produto;
        this.quantidade = quantidade;
    }

    public double calcularSubtotal() {
        return produto.getPreco() * quantidade;
    }

    public Produto getProduto() {
        return produto;
    }

    public int getQuantidade() {
        return quantidade;
    }
}

// --- CLASSE PEDIDO ---
public class Pedido {
    private int numeroPedido;
    private String status; // ex: "EM_ANDAMENTO", "PAGO", "CANCELADO"
    private List<ItemPedido> itens;
    private Pagamento pagamento;

    public Pedido(int numeroPedido) {
        this.numeroPedido = numeroPedido;
        this.status = "EM_ANDAMENTO";
        this.itens = new ArrayList<>();
    }

    public void adicionarItem(Produto produto, int quantidade) {
        if (status.equals("EM_ANDAMENTO")) {
            this.itens.add(new ItemPedido(produto, quantidade));
        }
    }

    public double calcularTotal() {
        double total = 0;
        for (ItemPedido item : itens) {
            total += item.calcularSubtotal();
        }
        return total;
    }

    public boolean realizarPagamento(String formaPagamento) {
        double total = calcularTotal();
        this.pagamento = new Pagamento(formaPagamento, total);

        if (this.pagamento.processar()) {
            this.status = "PAGO";
            return true;
        }
        return false;
    }

    public void cancelarPedido() {
        this.status = "CANCELADO";
    }
}

// --- CLASSE PAGAMENTO ---
public class Pagamento {
    private String tipo; // "CARTAO_CREDITO", "PIX", "ALIMENTACAO"
    private double valor;
    private boolean confirmado;

    public Pagamento(String tipo, double valor) {
        this.tipo = tipo;
        this.valor = valor;
        this.confirmado = false;
    }

    public boolean processar() {
        // Simulação de autorização do pagamento
        this.confirmado = true;
        return this.confirmado;
    }
}

// --- CLASSE CLIENTE (ATOR / INTERAÇÃO NO TOTEM) ---
public class Cliente {
    private String nome;

    public Cliente(String nome) {
        this.nome = nome;
    }

    public void montarPedido(Pedido pedido, Produto produto, int qtd) {
        pedido.adicionarItem(produto, qtd);
    }

    public void finalizarEPay(Pedido pedido, String meioPagamento) {
        pedido.realizarPagamento(meioPagamento);
    }
}

Dicas & Lembretes para a Entrega

  • Divida as tarefas da dupla: combine quem fica responsável pelo Diagrama de Casos de Uso e quem fica pelo Diagrama de Classes — ou façam os dois juntos e confiram mutuamente.
  • Reveja a notação antes de desenhar: atributos private viram -, métodos public viram +, e a ordem correta é nome: tipo (ex.: - preco: double).
  • <<include>> é obrigatório; <<extend>> é opcional: se o caso base sempre executa o outro, é include; se depende de uma condição, é extend.
  • Confira as multiplicidades: leia cada ponta da associação olhando para a extremidade oposta — ex.: em "1 → 1..*", a multiplicidade 1..* fica do lado da classe com vários objetos.
  • A classe Cliente é o ator: no Diagrama de Casos de Uso, o Cliente é o ator principal e o Sistema de Pagamento é o ator secundário/sistema externo.
  • Compare com o código: todo relacionamento do diagrama de classes deve ter correspondência no código-fonte (ex.: um atributo que guarda uma lista ou uma referência para outra classe).
