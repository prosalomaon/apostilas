Teoria & Conceitos

1. O Papel das Activities

Em Android, as aplicações são organizadas em torno de Activities, que representam uma única tela com uma interface gráfica. Cada Activity é uma classe que herda de AppCompatActivity e é responsável por gerenciar uma tela específica do fluxo de trabalho do usuário.

Pense em cada Activity como uma "página" de um livro. O usuário navega de uma página para outra, e o sistema Android gerencia uma pilha de Activities (Back Stack) para controlar a ordem de exibição e permitir a navegação com o botão voltar.

Existem dois modelos principais de navegação no desenvolvimento Android moderno:

  • Navegação por Activities (Clássica): Cada tela é uma Activity diferente, e a transição entre elas é feita através de Intents.
  • Navegação por Composables (Moderna): Diferentes telas são apenas funções @Composable diferentes, e o NavController gerencia uma pilha de rotas (Backstack) dentro de uma única Activity.

2. Intents: O Mecanismo de Transição

Um Intent é o mecanismo padrão do Android para solicitar uma ação de outro componente do app. Na navegação entre Activities, o Intent funciona como uma "carta de apresentação" que diz ao sistema: "Quero abrir esta outra tela, e aqui estão os dados que ela precisa".

Intents são classificados em dois tipos:

  • Intent Explícito: Especifica exatamente qual componente deve ser aberto (ex: abrir a DetailActivity a partir da MainActivity).
  • Intent Implícito: Declara uma ação genérica (ex: abrir o navegador, tirar uma foto) e o sistema escolhe qual componente pode atender à solicitação.

Para navegação dentro do nosso app, utilizamos exclusivamente Intents Explícitos.

3. Navegação Declarativa com Compose

Seguindo as recomendações LTS (Long Term Support) do Google, a navegação moderna em Android utiliza a biblioteca androidx.navigation junto com o Jetpack Compose. O NavController é o componente central que gerencia uma pilha de telas (Backstack) através de rotas definidas por strings.

A vantagem desta abordagem é que toda a navegação acontece dentro de uma única Activity, o que resulta em:

  • Transições mais fluidas e animadas
  • Compartilhamento de estado entre telas de forma simplificada
  • Testes mais fáceis, já que a navegação é apenas uma mudança de rota
  • Menos overhead de criação e destruição de Activities pelo sistema

4. Ciclo de Vida e Navegação

É crucial entender como o sistema gerencia a memória durante a navegação. Quando uma Activity é suspensa ou destruída (por exemplo, quando o usuário navega para uma nova tela), o sistema pode liberar recursos para a nova Activity ativa. Cada Activity passa por um ciclo de vida com estados como onCreate(), onPause(), onStop() e onDestroy().

No modelo Compose, como a navegação ocorre dentro de uma única Activity, o ciclo de vida da Activity se mantém estável, e apenas as composições são recompostas conforme o usuário navega entre as rotas.

Exemplo de Código

Abordagem 1: Navegação por Activities com Intents (Tradicional)

Esta é a abordagem clássica do Android. Cada tela é uma Activity separada registrada no AndroidManifest.xml.

A. Definindo a Activity de Destino

Crie uma nova classe que herde de AppCompatActivity:

// DetailActivity.kt
class DetailActivity : AppCompatActivity() {

    companion object {
        const val EXTRA_ITEM_ID = "DetailActivity:item_id"
        const val EXTRA_ITEM_NAME = "DetailActivity:item_name"
    }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_detail)

        // Recuperando os parâmetros enviados pela Intent
        val itemId = intent.getLongExtra(EXTRA_ITEM_ID, -1)
        val itemName = intent.getStringExtra(EXTRA_ITEM_NAME) ?: "Sem nome"

        // Utilizando os dados para exibir informações na tela
        findViewById<TextView>(R.id.tvDetail).text =
            "Item: $itemName (ID: $itemId)"
    }
}

B. Registrando no AndroidManifest.xml

Toda Activity precisa ser declarada no manifesto do aplicativo para que o sistema a reconheça:

<activity
    android:name=".DetailActivity"
    android:label="Detalhes do Item"
    android:parentActivityName=".MainActivity" />

C. Iniciando a Activity de Destino

Na Activity de origem (geralmente a MainActivity), utilize o Intent para iniciar a nova tela:

// Na Activity de origem (MainActivity)
val intent = Intent(this, DetailActivity::class.java).apply {
    putExtra(DetailActivity.EXTRA_ITEM_ID, item.id)
    putExtra(DetailActivity.EXTRA_ITEM_NAME, item.name)
}
startActivity(intent)

Boa Prática: Defina as chaves de identificação como constantes no companion object da Activity de destino. Isso evita erros de digitação e facilita a manutenção do código.

Abordagem 2: Navegação com Compose Navigation (Moderna)

Esta é a abordagem recomendada pelo Google para novos projetos. Utilizamos o NavHost e o NavController para gerenciar as rotas.

A. Configurando o NavHost

// MainActivity.kt
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            val navController = rememberNavController()

            NavHost(
                navController = navController,
                startDestination = "home"
            ) {
                composable("home") {
                    HomeScreen(
                        onItemClick = { itemId, itemName ->
                            navController.navigate("detail/$itemId/$itemName")
                        }
                    )
                }
                composable(
                    route = "detail/{itemId}/{itemName}",
                    arguments = listOf(
                        navArgument("itemId") { type = NavType.LongType },
                        navArgument("itemName") { type = NavType.StringType }
                    )
                ) { backStackEntry ->
                    val itemId = backStackEntry.arguments?.getLong("itemId") ?: 0L
                    val itemName = backStackEntry.arguments?.getString("itemName") ?: ""
                    DetailScreen(itemId = itemId, itemName = itemName)
                }
            }
        }
    }
}

B. Criando as Telas (Composables)

// HomeScreen.kt
@Composable
fun HomeScreen(onItemClick: (Long, String) -> Unit) {
    Column(modifier = Modifier.padding(16.dp)) {
        Text(
            text = "Lista de Itens",
            style = MaterialTheme.typography.headlineMedium
        )
        Spacer(modifier = Modifier.height(16.dp))

        // Simulando uma lista de itens
        val items = listOf(
            Pair(1L, "Notebook"),
            Pair(2L, "Mouse"),
            Pair(3L, "Teclado")
        )

        items.forEach { (id, name) ->
            Card(
                modifier = Modifier
                    .fillMaxWidth()
                    .padding(vertical = 4.dp)
                    .clickable { onItemClick(id, name) }
            ) {
                Text(
                    text = name,
                    modifier = Modifier.padding(16.dp)
                )
            }
        }
    }
}

// DetailScreen.kt
@Composable
fun DetailScreen(itemId: Long, itemName: String) {
    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
        verticalArrangement = Arrangement.Center
    ) {
        Text(
            text = "Detalhes do Item",
            style = MaterialTheme.typography.headlineMedium
        )
        Spacer(modifier = Modifier.height(16.dp))
        Text(text = "Nome: $itemName")
        Text(text = "ID: $itemId")
    }
}

C. Passagem de Parâmetros com Tipos Seguros

Para evitar erros de digitação nas rotas, é recomendado criar um objeto sealed class ou uma classe object que centraliza todas as rotas do app: 

// Routes.kt
object Routes {
    const val HOME = "home"
    fun detail(itemId: Long, itemName: String): String {
        return "detail/$itemId/$itemName"
    }
}

// Uso no NavHost:
navController.navigate(Routes.detail(itemId = 5, itemName = "Notebook"))

D. Navegação com Argumentos Opcionais

// Rota com argumento opcional (default value)
composable(
    route = "detail/{itemId}/{itemName}",
    arguments = listOf(
        navArgument("itemId") { type = NavType.LongType },
        navArgument("itemName") {
            type = NavType.StringType
            defaultValue = "Sem nome"
        }
    )
) { backStackEntry ->
    val itemId = backStackEntry.arguments?.getLong("itemId") ?: 0L
    val itemName = backStackEntry.arguments?.getString("itemName") ?: "Sem nome"
    DetailScreen(itemId = itemId, itemName = itemName)
}

Laboratório Prático: Fluxo Mestre-Detalhe

Vamos implementar um fluxo completo de navegação onde o usuário seleciona um item de uma lista e é redirecionado para uma tela de detalhes com as informações do item escolhido.

1. Modelo de Dados

Primeiro, definimos a classe que representa nossos itens:

// data/Item.kt
data class Item(
    val id: Long,
    val name: String,
    val description: String,
    val category: String
)

// Lista simulada de dados (em um app real, viria de uma API ou banco de dados)
val sampleItems = listOf(
    Item(1, "Notebook Dell", "Notebook para desenvolvimento", "Eletrônicos"),
    Item(2, "Mouse Logitech", "Mouse ergonômico", "Periféricos"),
    Item(3, "Teclado Mecânico", "Switch Blue, ABNT2", "Periféricos"),
    Item(4, "Monitor 27\"", "4K IPS, 60Hz", "Eletrônicos"),
    Item(5, "Cadeira Gamer", "Ajuste lombar e braços", "Móveis")
)

2. Tela de Lista (Mestre)

A tela principal exibe uma lista de itens. Ao clicar em um item, o app navega para a tela de detalhes, passando o ID e o nome como parâmetros. 

// ui/HomeScreen.kt
@Composable
fun HomeScreen(navController: NavHostController) {
    LazyColumn(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp)
    ) {
        items(sampleItems) { item ->
            Card(
                modifier = Modifier
                    .fillMaxWidth()
                    .padding(vertical = 4.dp)
                    .clickable {
                        navController.navigate(
                            "detail/${item.id}/${item.name}"
                        )
                    },
                elevation = CardDefaults.cardElevation(defaultElevation = 2.dp)
            ) {
                Row(
                    modifier = Modifier
                        .padding(16.dp)
                        .fillMaxWidth(),
                    horizontalArrangement = Arrangement.SpaceBetween,
                    verticalAlignment = Alignment.CenterVertically
                ) {
                    Column {
                        Text(
                            text = item.name,
                            style = MaterialTheme.typography.titleMedium
                        )
                        Text(
                            text = item.category,
                            style = MaterialTheme.typography.bodySmall,
                            color = MaterialTheme.colorScheme.onSurfaceVariant
                        )
                    }
                    Icon(
                        imageVector = Icons.Default.ChevronRight,
                        contentDescription = "Ver detalhes"
                    )
                }
            }
        }
    }
}

3. Tela de Detalhes (Detalhe)

A tela de detalhes recebe os parâmetros pela URL da rota e exibe as informações completas do item. 

// ui/DetailScreen.kt
@Composable
fun DetailScreen(
    itemId: Long,
    itemName: String,
    onBack: () -> Unit
) {
    // Em um app real, buscaríamos os dados completos pelo ID
    val item = sampleItems.find { it.id == itemId }

    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp)
    ) {
        // Botão voltar
        IconButton(onClick = onBack) {
            Icon(
                imageVector = Icons.Default.ArrowBack,
                contentDescription = "Voltar"
            )
        }

        Spacer(modifier = Modifier.height(8.dp))

        if (item != null) {
            Text(
                text = item.name,
                style = MaterialTheme.typography.headlineMedium
            )
            Spacer(modifier = Modifier.height(8.dp))
            AssistChip(
                onClick = {},
                label = { Text(item.category) }
            )
            Spacer(modifier = Modifier.height(16.dp))
            Text(
                text = item.description,
                style = MaterialTheme.typography.bodyLarge
            )
        } else {
            Text(text = "Item não encontrado (ID: $itemId)")
        }
    }
}

4. Configuração da Navegação

Por fim, conectamos todas as telas no NavHost: 

// navigation/AppNavigation.kt
@Composable
fun AppNavigation() {
    val navController = rememberNavController()

    NavHost(
        navController = navController,
        startDestination = "home"
    ) {
        composable("home") {
            HomeScreen(navController = navController)
        }
        composable(
            route = "detail/{itemId}/{itemName}",
            arguments = listOf(
                navArgument("itemId") { type = NavType.LongType },
                navArgument("itemName") { type = NavType.StringType }
            )
        ) { backStackEntry ->
            val itemId = backStackEntry.arguments?.getLong("itemId") ?: 0L
            val itemName = backStackEntry.arguments?.getString("itemName") ?: ""
            DetailScreen(
                itemId = itemId,
                itemName = itemName,
                onBack = { navController.popBackStack() }
            )
        }
    }
}

Quadro Comparativo: Activity Navigation vs. Compose Navigation

Critério Activity Navigation (Tradicional) Compose Navigation (Moderna)
Estrutura Cada tela é uma classe Activity separada. Cada tela é uma função @Composable.
Transição Feita via Intent com startActivity(). Feita via NavController.navigate().
Passagem de Dados Extras no Bundle da Intent (putExtra/getExtra). Argumentos na URL da rota ({param}).
Performance Pesada: cria e destrói Activities pelo sistema. Leve: apenas recomposição de funções.
Compartilhamento de Estado Complexo: requer ViewModel compartilhado ou SavedStateHandle. Simples: estado pode ser compartilhado via NavController ou ViewModel.
Animações Requer configuração manual ou shared element transitions. Animations integradas (fade, slide, etc.).
Registro Exige declaração no AndroidManifest.xml. Não exige registro externo.
Boa Prática LTS Usado legado e compatibilidade. Recomendado para novos projetos.

Dicas & Lembretes

1. Centralize as Rotas em um Objeto

Evite duplicar strings de rotas por todo o projeto. Crie um object Routes que centraliza todas as rotas. Isso evita erros de digitação e facilita a manutenção quando uma rota é alterada.

2. Use Constantes para Chaves de Extras

Quando usar Intents (navegação por Activities), defina as chaves de extras como constantes no companion object da Activity de destino. Isso evita o erro clássico de "chave incorreta" que causa dados nulos silenciosos.

3. Valide Argumentos na Tela de Destino

Sempre trate o caso de argumentos ausentes ou inválidos. Use o operador ?: (Elvis) para definir valores padrão e evite crashes por dados nulos inesperados.

4. Entenda o popBackStack()

O método navController.popBackStack() remove a tela atual da pilha e retorna à anterior. É o equivalente moderno ao pressionar o botão "Voltar" do dispositivo.

5. Lembre do Ciclo de Vida

No modelo Compose Navigation, a Activity permanece ativa durante toda a navegação. Isso significa que estados de UI e dados em memória são preservados entre as rotas, diferentemente do modelo de Activities onde cada transição pode destruir e recriar a tela anterior.
