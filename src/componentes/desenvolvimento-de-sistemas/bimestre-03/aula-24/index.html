Teoria & Conceitos

1. O que é JavaFX?

Anunciado originalmente em 2007, o JavaFX evoluiu de uma linguagem de script para um conjunto robusto de bibliotecas Java. Ele foi projetado para oferecer uma experiência de desenvolvimento superior ao Swing, integrando em uma única API o suporte para interfaces ricas, animações, áudio e vídeo.

Vantagens sobre o Swing:

  • Facilidade de Uso: API única para GUI e multimídia.
  • Scene Builder: Ferramenta visual de "arrastar e soltar" que produz o mesmo código independentemente da IDE utilizada (NetBeans, Eclipse ou IntelliJ).
  • Estilização com CSS: Controle total da aparência através de Cascading Style Sheets.
  • Segurança de Threads: Projetado para melhor performance em sistemas multiprocessados modernos.

2. Arquitetura Model-View-Controller (MVC)

Aplicativos JavaFX seguem o padrão de design MVC, que promove uma separação clara entre os dados e a interface:

  • Model (Modelo): Contém os dados do aplicativo.
  • View (Visualização): Definida em arquivos FXML, descreve como a interface deve parecer.
  • Controller (Controlador): Classe Java que implementa a lógica para processar as entradas do usuário e atualizar o modelo ou a visualização.

3. Estrutura de um Aplicativo JavaFX

A estrutura de uma janela JavaFX assemelha-se a uma peça de teatro:

  • Stage (Palco): A janela principal do aplicativo (instância da classe Stage).
  • Scene (Cena): O contêiner de conteúdo dentro do palco. Uma cena define a interface como um Grafo de Cena.
  • Grafo de Cena (Scene Graph): Uma estrutura em árvore que organiza todos os elementos visuais (nós).
  • Nodes (Nós): Cada elemento visual (botão, rótulo, contêiner de layout) é um nó.

4. Scene Builder e FXML

O Scene Builder é uma ferramenta visual que gera arquivos FXML (FX Markup Language), um vocabulário XML para definir a interface sem escrever código Java manual. Isso permite que o desenvolvedor se concentre na interface de forma declarativa.

Contêineres de Layout Comuns:

  • VBox: Organiza os nós verticalmente, de cima para baixo.
  • GridPane: Organiza os componentes em uma grade flexível de linhas e colunas.
Contêiner Comportamento Uso típico
VBox Empilha os nós verticalmente Formulários em coluna
HBox Empilha os nós horizontalmente Linhas de botões
GridPane Grade flexível de linhas e colunas Formulários com rótulos/campos
BorderPane Regiões top/bottom/left/right/center Layout principal da tela

Exemplo de Código

1. Ponto de Partida

A classe principal deve estender Application. O método start é o local onde a "mágica" acontece: 

import javafx.application.Application;
import javafx.fxml.FXMLLoader;
import javafx.scene.Parent;
import javafx.scene.Scene;
import javafx.stage.Stage;

public class MeuApp extends Application {
    @Override
    public void start(Stage stage) throws Exception {
        // Carrega o arquivo FXML criado no Scene Builder
        Parent root = FXMLLoader.load(getClass().getResource("Interface.fxml"));

        Scene scene = new Scene(root);       // Cria a cena com o layout carregado
        stage.setTitle("Minha Interface JavaFX"); // Título da janela
        stage.setScene(scene);               // Coloca a cena no palco
        stage.show();                        // Exibe a janela
    }

    public static void main(String[] args) {
        launch(args);                        // Inicia o tempo de execução do JavaFX
    }
}

2. A Classe de Controle e a Anotação @FXML

Para que o controlador possa manipular os componentes definidos no FXML, utilizamos a anotação @FXML. Isso vincula variáveis de instância e métodos aos IDs (fx:id) definidos no Scene Builder: 

import javafx.event.ActionEvent;
import javafx.fxml.FXML;
import javafx.scene.control.Label;

public class MeuControlador {
    @FXML
    private Label meuRotulo; // Vinculado ao fx:id="meuRotulo"

    @FXML
    private void tratarClique(ActionEvent event) {
        meuRotulo.setText("Botão Clicado!"); // Lógica de resposta ao evento
    }
}

3. O Arquivo FXML correspondente

O arquivo gerado pelo Scene Builder referencia o controlador e os fx:id usados na classe Java: 

<?xml version="1.0" encoding="UTF-8"?>

<?import javafx.scene.control.Button?>
<?import javafx.scene.control.Label?>
<?import javafx.scene.layout.VBox?>

<VBox spacing="10" xmlns="http://javafx.com/javafx"
      xmlns:fx="http://javafx.com/fxml"
      fx:controller="MeuControlador">
   <Label fx:id="meuRotulo" text="Aguardando clique..." />
   <Button text="Clique aqui" onAction="#tratarClique" />
</VBox>

Observe a correspondência: o fx:controller aponta para a classe MeuControlador, o fx:id="meuRotulo" do rótulo casa com a variável @FXML private Label meuRotulo e o onAction="#tratarClique" do botão chama o método anotado com @FXML.

Dicas & Lembretes de Herói

  • Separação de Preocupações: Mantenha o FXML apenas para o visual e o Java apenas para a lógica. Isso facilita muito a manutenção.
  • Foco no Usuário: Um controle só pode receber entrada do teclado se tiver o "foco". Use o método requestFocus() para direcionar o cursor quando necessário.
  • IDs Únicos: Certifique-se de que os valores de fx:id na interface correspondam exatamente aos nomes das variáveis no controlador.
  • Cálculos Precisos: Ao lidar com valores monetários em interfaces gráficas (como calculadoras), prefira sempre BigDecimal para garantir a precisão dos centavos.

Como aplicar na Prática

  • Comece pela View no Scene Builder: desenhe a tela com "arrastar e soltar", defina os fx:id dos componentes que o controlador precisará e salve o FXML.
  • Ligue o FXML ao Java: no método start, carregue o arquivo com FXMLLoader.load(...) e use o atributo fx:controller para apontar a classe de controle.
  • Implemente a lógica no Controller: anote com @FXML apenas as variáveis e os métodos que precisam ser visíveis para o FXML; o resto da lógica permanece privado em Java.
  • Escolha o layout certo: VBox/HBox para sequências simples, GridPane para formulários e BorderPane para o esqueleto geral da tela.
  • Não escreva GUI na mão: para telas complexas, prefira gerar o FXML no Scene Builder e apenas ajustá-lo — o resultado é mais consistente e independente da IDE.
