Enunciado

A Padaria do Sabor, cliente da sua equipe, precisa de uma base de dados nova e a documentação de padronização de tipos. Você vai implementar o mesmo modelo físico nos dois SGBDs e entregar um parecer técnico comparando o comportamento de cada tipo.

O grande diferencial desta atividade é justamente a portabilidade: você vai executar o mesmo script nos dois servidores e comparar os resultados, identificando onde os dois SGBDs divergem.

Preparação

  1. Ambiente: garanta os dois servidores disponíveis — MySQL 8.0+ e PostgreSQL 12+ (XAMPP, WampServer ou Docker). Use clientes como MySQL Workbench, pgAdmin ou o terminal.
  2. Bancos: crie padaria_mysql e padaria_postgres com a mesma estrutura.
  3. Comparação: mantenha as duas janelas (ou terminais) lado a lado. Cada bloco abaixo exige rodar o mesmo comando nos dois servidores e anotar a diferença.
  4. Validação: ao final, use information_schema.columns nos dois SGBDs para conferir que os tipos declarados foram realmente materializados.

  • 01_ddl_basico.sql — chaves primárias, texto e valores monetários.

Orientações Finais

  • Documento comparativo: a entrega é o parecer técnico com as tabelas preenchidas dos Blocos 1, 2, 3 e 4, incluindo as mensagens de erro literais de cada SGBD.
  • Não teste no escuro: toda diferença afirmada no parecer deve vir de um comando executado nos dois servidores, com o resultado colado.
  • Dinheiro é DECIMAL: qualquer coluna cujos valores serão somados ou subtraídos precisa de DECIMAL/NUMERIC.
  • Fuso é decisão de arquitetura: se a aplicação atende clientes em fusos diferentes, grave o instante em UTC e converta apenas na apresentação.
