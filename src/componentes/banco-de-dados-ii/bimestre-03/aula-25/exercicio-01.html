Enunciado

Você foi promovido(a) a engenheiro(a) de banco de dados da empresa MegaShop. Agora, o desafio é usar gatilhos avançados para resolver problemas reais de arquitetura e performance, tanto no MySQL quanto no PostgreSQL.

Seu objetivo é implementar gatilhos que tornam visões atualizáveis, emulam índices baseados em função, fazem saneamento e rejeição de dados, geram auditoria e mantêm totais consolidados.

Preparação

  1. Ambiente MySQL: Execute o script da seção "1. Script de Preparação" no MySQL.
  2. Ambiente PostgreSQL: Execute os blocos indicados no PostgreSQL (psql ou pgAdmin).
  3. Resolução: Crie cada gatilho seguindo a sintaxe de cada SGBD, conforme os exemplos da aula.
  4. Validação: Após cada gatilho, execute operações de escrita e confira os efeitos nas tabelas de destino, log e resumo.

1. Script de Preparação

Execute o script abaixo para criar as tabelas do cenário:

-- MySQL
CREATE DATABASE megashop_db;
USE megashop_db;

CREATE TABLE fatos_vendas (
    id_venda INT AUTO_INCREMENT PRIMARY KEY,
    id_produto INT NOT NULL,
    qtd INT NOT NULL
);

CREATE TABLE produtos (
    codigo INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    valor DECIMAL(10,2) NOT NULL,
    valor_log10 DECIMAL(10,4) DEFAULT NULL
);

CREATE TABLE resumo_vendas (
    id_resumo INT AUTO_INCREMENT PRIMARY KEY,
    total INT DEFAULT 0
);

CREATE TABLE auditoria_log (
    id_log INT AUTO_INCREMENT PRIMARY KEY,
    tabela VARCHAR(100) NOT NULL,
    operacao VARCHAR(10) NOT NULL,
    usuario VARCHAR(100),
    valor_antigo TEXT,
    valor_novo TEXT,
    data_hora DATETIME DEFAULT NOW()
);

INSERT INTO produtos (nome, valor) VALUES
('Notebook', 2999.90),
('Monitor', 899.90),
('Teclado', 149.90);

2. Desafios de Prática

Bloco 1: Visão atualizável com INSTEAD OF (PostgreSQL)

  1. Crie uma visão vw_resumo_vendas que resuma as vendas por produto (agrupando por id_produto e somando qtd).
  2. Crie a função de gatilho func_venda_view() que, quando um INSERT for feito na visão, insira os dados na tabela física fatos_vendas e retorne NEW.
  3. Vincule a função à visão com: 
    CREATE TRIGGER tr_venda_view
INSTEAD OF INSERT ON vw_resumo_vendas
FOR EACH ROW EXECUTE PROCEDURE func_venda_view();
  4. Teste inserindo na visão e confirme que a linha foi gravada em fatos_vendas.
  5. Explique por que esse recurso não existe nativamente no MySQL e o que se pode fazer para obter um comportamento equivalente.

Bloco 2: Simulação de índice baseado em função (MySQL)

  1. Crie um gatilho bi_produto_log10 que, antes de inserir um produto, preencha a coluna valor_log10 com LOG10(NEW.valor).
  2. Crie um segundo gatilho bu_produto_log10 que faça o mesmo antes de um UPDATE.
  3. Insira e depois atualize um produto e confirme que valor_log10 sempre reflete o valor atual.
  4. Explique por que essa coluna extra permite acelerar consultas como WHERE valor_log10 < 2 no MySQL.

Bloco 3: Saneamento e rejeição de dados (MySQL)

  1. Crie o gatilho bi_produto_saneia que, antes de inserir um produto, aplique UPPER(TRIM(NEW.nome)) para normalizar o nome.
  2. Crie o gatilho bi_venda_valida que, antes de inserir em fatos_vendas, rejeite vendas com qtd <= 0 usando SIGNAL SQLSTATE '45000'.
  3. Teste os dois comportamentos: insira um nome com espaços e letras minúsculas (deve ser normalizado) e tente inserir uma venda com quantidade negativa (deve ser rejeitada).
  4. Diferencie saneamento de rejeição com base no que você implementou.

Bloco 4: Auditoria com OLD/NEW e gatilho de instrução (MySQL)

  1. Crie o gatilho ad_produto_auditoria que, após um DELETE em produtos, registre na tabela auditoria_log o valor antigo removido (CONCAT(OLD.codigo, ' - ', OLD.nome)).
  2. Remova um produto e confirme o registro de auditoria.
  3. No PostgreSQL, crie a função de gatilho func_recalcula_totais() e o gatilho tr_recalcula_totais do tipo AFTER INSERT ON fatos_vendas FOR EACH STATEMENT, que atualiza a tabela resumo_vendas com o total de qtd.
  4. Compare FOR EACH ROW e FOR EACH STATEMENT: qual usaria para auditoria detalhada e qual para recálculo após uma carga massiva? Justifique.

Orientações Finais

  • INSTEAD OF: Só existe em visões no PostgreSQL; no MySQL, use gatilhos nas tabelas base ou procedures para comportamento equivalente.
  • Saneamento: Aplique normalizações (UPPER/TRIM) em BEFORE INSERT/UPDATE.
  • Rejeição: Para regras complexas, dispare SIGNAL no MySQL ou RAISE EXCEPTION no PostgreSQL para cancelar a transação.
  • Cascata: Evite gatilhos que se disparem em ciclo, causando loops infinitos.
  • Tente sozinho: Resolva os blocos sem consultar a aula primeiro; volte a ela somente se travar em algum conceito.
