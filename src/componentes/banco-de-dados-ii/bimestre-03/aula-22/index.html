Teoria & Conceitos

1. O que é uma Stored Procedure?

Uma Stored Procedure (Procedimento Armazenado) é um objeto definido pelo usuário que consiste em uma ou mais instruções SQL armazenadas no servidor para execução posterior. Diferente de uma consulta enviada do cliente para o servidor a cada execução, a procedure reside no banco de dados e pode ser invocada apenas pelo seu nome.

Isso faz dela a ferramenta ideal para automatizar tarefas e encapsular regras de negócio complexas que envolvem múltiplas tabelas.

2. Principais Vantagens

  • Encapsulamento: Permite realizar operações complexas sem que a aplicação precise conhecer os detalhes das tabelas ou repetir o código SQL.
  • Segurança: É possível conceder permissão de execução em uma procedure a um usuário sem dar a ele acesso direto às tabelas base.
  • Performance: Reduz o tráfego de rede, pois apenas o comando de chamada é enviado ao servidor, onde todo o processamento ocorre.

3. O que "sobra" na rede?

Compare os dois caminhos abaixo: na consulta tradicional, o SQL inteiro viaja pela rede a cada chamada; com a procedure, apenas o nome e os parâmetros trafegam — toda a lógica já está no servidor.

Parâmetros: IN, OUT e INOUT

Diferente das funções simples, que geralmente recebem apenas entradas, os procedimentos podem devolver múltiplos valores através de parâmetros específicos:

Parâmetro Direção Descrição
IN Entrada O valor é passado da aplicação para a procedure (comportamento padrão).
OUT Saída A procedure atribui um valor ao parâmetro, que pode ser lido pela aplicação após a execução.
INOUT Entrada e Saída O parâmetro entra com um valor, pode ser modificado pela procedure e retorna o novo valor.

Exemplo de INOUT no MySQL

A procedure abaixo recebe um valor, aplica um percentual de desconto e devolve o novo valor no mesmo parâmetro: 

DELIMITER //

CREATE PROCEDURE AplicarDesconto(INOUT valor DECIMAL(10,2), IN percentual DECIMAL(5,2))
BEGIN
    SET valor = valor - (valor * percentual / 100);
END //

DELIMITER ;

-- Uso: variável de usuário (@) entra com 1000.00 e sai com 900.00
SET @preco = 1000.00;
CALL AplicarDesconto(@preco, 10);
SELECT @preco; -- 900.00

Implementação Prática: MySQL vs. PostgreSQL

Exemplo no MySQL

No MySQL, ao definir procedimentos com múltiplas linhas, é essencial usar o comando DELIMITER para que o ponto e vírgula (;) interno não seja interpretado como o fim do comando de criação. 

-- Altera o delimitador para permitir o uso de ';' dentro do bloco
DELIMITER //

CREATE PROCEDURE ObterEstatisticasVendedor(IN id_vendedor INT, OUT total_pedidos INT)
BEGIN
    -- Busca o total de pedidos e atribui ao parâmetro de saída
    SELECT COUNT(*) INTO total_pedidos
    FROM pedido
    WHERE codigo_vendedor = id_vendedor;
END //

DELIMITER ;

-- Como invocar (CALL)
CALL ObterEstatisticasVendedor(11, @total);
SELECT @total; -- Exibe o valor retornado

Exemplo no PostgreSQL (PL/pgSQL)

No PostgreSQL, os procedimentos são implementados com o comando PROCEDURE (versões 11+) ou como funções, utilizando a linguagem PL/pgSQL. A lógica fica entre $$ e o idioma é declarado com LANGUAGE plpgsql. 

CREATE OR REPLACE PROCEDURE atualizar_estoque(prod_id INT, qtd_venda INT)
LANGUAGE plpgsql
AS $$
BEGIN
    -- Lógica de negócio encapsulada
    UPDATE produtos
    SET saldo_estoque = saldo_estoque - qtd_venda
    WHERE codigo = prod_id;

    -- No PostgreSQL, você pode disparar avisos ou logs
    RAISE NOTICE 'Estoque atualizado para o produto %', prod_id;
END;
$$;

-- Como invocar (CALL)
CALL atualizar_estoque(108, 5);

Stored Procedure vs. Function

Embora ambos sejam "Stored Programs" (programas armazenados), existem distinções fundamentais:

Aspecto Stored Procedure Function
Retorno Pode retornar vários valores (via OUT/INOUT) ou nenhum. Sempre retorna um valor através da cláusula RETURN.
Uso em expressões Não. É chamada via CALL e não pode ser usada em expressões. Sim. Pode ser usada dentro de um SELECT ou na cláusula WHERE.
Finalidade Processos que modificam dados ou produzem múltiplos resultados. Cálculos e valores escalares (ex: calcular imposto).

Exemplo de Function no MySQL

Uma função para cálculo de imposto, que pode ser usada diretamente dentro de uma consulta: 

DELIMITER //

CREATE FUNCTION CalcularImposto(valor DECIMAL(10,2)) RETURNS DECIMAL(10,2)
BEGIN
    RETURN valor * 0.20; -- 20% de imposto
END //

DELIMITER ;

-- Funções podem ser usadas dentro de SELECT
SELECT CalcularImposto(1000.00) AS imposto; -- 200.00

Dicas & Lembretes

  • Privilégios: Para criar uma procedure, você precisa do privilégio CREATE ROUTINE; para rodá-la, do privilégio EXECUTE.
  • Manutenção: Se você renomear uma tabela, lembre-se de atualizar todas as procedures que fazem referência a ela.
  • Variáveis Locais: Dentro de um bloco BEGIN...END, você pode declarar variáveis locais (via DECLARE) que existem apenas durante a execução daquele procedimento.
  • Tratamento de Erros: Procedures podem incluir "Handlers" para capturar erros específicos e decidir se devem continuar ou cancelar a transação.
  • Delimitador esquecido: No MySQL, executar uma procedure de múltiplas linhas sem o DELIMITER gera erro de sintaxe no primeiro ; interno.

Como aplicar na Prática

  • Fechamento de mês: Crie uma procedure que calcula comissões, gera lançamentos contábeis e atualiza relatórios em uma única chamada.
  • Controle de estoque: Encapsule a regra "só vender se houver saldo" dentro da procedure atualizar_estoque, garantindo que nenhuma aplicação ignore essa validação.
  • Segurança por camadas: Conceda apenas EXECUTE ao usuário da aplicação, sem acesso direto às tabelas base — as regras de negócio ficam protegidas no servidor.
  • Processos agendados: Procedures são o alvo natural de tarefas agendadas (eventos, cron) para execução de rotinas de limpeza e consolidação de dados.
