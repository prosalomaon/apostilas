Cenário: Sistema de Vendas "TechStore"

Esta demonstração pratica todos os conceitos da aula — parâmetros IN, OUT e INOUT, Stored Procedures e Functions — em um único sistema integrado de vendas de uma loja de tecnologia. O banco gerencia vendedores, produtos, pedidos e comissões.

Copie e execute cada bloco de código na ordem apresentada no MySQL Workbench ou terminal. Ao final, você terá 4 procedures e 1 function funcionando.

Passo 1 — Estrutura das Tabelas

Criamos as tabelas do banco de dados da loja. A tabela comissoes será usada pela procedure de fechamento mensal para armazenar os valores calculados. 

-- Limpeza preventiva do ambiente de teste
SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS itens_pedido;
DROP TABLE IF EXISTS comissoes;
DROP TABLE IF EXISTS pedidos;
DROP TABLE IF EXISTS produtos;
DROP TABLE IF EXISTS vendedores;
SET FOREIGN_KEY_CHECKS = 1;

-- Tabela 1: Cadastro de Vendedores
CREATE TABLE vendedores (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL,
    meta_mensal DECIMAL(10,2) NOT NULL DEFAULT 0.00
);

-- Tabela 2: Catálogo de Produtos
CREATE TABLE produtos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    preco DECIMAL(10,2) NOT NULL,
    estoque INT NOT NULL DEFAULT 0
);

-- Tabela 3: Registro de Pedidos
CREATE TABLE pedidos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    id_vendedor INT NOT NULL,
    data_pedido DATE NOT NULL,
    valor_total DECIMAL(10,2) NOT NULL DEFAULT 0.00,
    status VARCHAR(30) NOT NULL DEFAULT 'PENDENTE',
    FOREIGN KEY (id_vendedor) REFERENCES vendedores(id)
);

-- Tabela 4: Itens de Cada Pedido
CREATE TABLE itens_pedido (
    id INT PRIMARY KEY AUTO_INCREMENT,
    id_pedido INT NOT NULL,
    id_produto INT NOT NULL,
    quantidade INT NOT NULL,
    preco_unitario DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (id_pedido) REFERENCES pedidos(id),
    FOREIGN KEY (id_produto) REFERENCES produtos(id)
);

-- Tabela 5: Registro de Comissões Calculadas
CREATE TABLE comissoes (
    id INT PRIMARY KEY AUTO_INCREMENT,
    id_vendedor INT NOT NULL,
    mes_ano VARCHAR(7) NOT NULL,
    total_vendas DECIMAL(10,2) NOT NULL,
    percentual_comissao DECIMAL(5,2) NOT NULL,
    valor_comissao DECIMAL(10,2) NOT NULL,
    data_calculo DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (id_vendedor) REFERENCES vendedores(id)
);

Passo 3 — Procedure com IN: Registrar Novo Pedido

Conceito: O parâmetro IN é o padrão — recebe um valor da aplicação. Esta procedure encapsula toda a lógica de registro de um pedido: valida estoque, cria o registro e atualiza o saldo. 

DELIMITER //

CREATE PROCEDURE RegistrarPedido(
    IN p_id_vendedor INT,
    IN p_id_produto INT,
    IN p_quantidade INT
)
BEGIN
    DECLARE v_estoque INT;
    DECLARE v_preco DECIMAL(10,2);
    DECLARE v_id_pedido INT;
    DECLARE v_valor_total DECIMAL(10,2);

    -- 1. Verifica se o produto existe e tem estoque suficiente
    SELECT estoque, preco INTO v_estoque, v_preco
    FROM produtos
    WHERE id = p_id_produto;

    IF v_estoque IS NULL THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'ERRO: Produto não encontrado.';
    END IF;

    IF v_estoque < p_quantidade THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'ERRO: Estoque insuficiente para esta quantidade.';
    END IF;

    -- 2. Calcula o valor total
    SET v_valor_total = v_preco * p_quantidade;

    -- 3. Cria o pedido
    INSERT INTO pedidos (id_vendedor, data_pedido, valor_total, status)
    VALUES (p_id_vendedor, CURDATE(), v_valor_total, 'PENDENTE');

    SET v_id_pedido = LAST_INSERT_ID();

    -- 4. Registra o item do pedido
    INSERT INTO itens_pedido (id_pedido, id_produto, quantidade, preco_unitario)
    VALUES (v_id_pedido, p_id_produto, p_quantidade, v_preco);

    -- 5. Atualiza o estoque do produto
    UPDATE produtos
    SET estoque = estoque - p_quantidade
    WHERE id = p_id_produto;

    -- 6. Retorna o ID do pedido criado
    SELECT v_id_pedido AS 'Pedido Criado', v_valor_total AS 'Valor Total (R$)';

END //

DELIMITER ;

Testando a Procedure

-- Pedido válido: Ana vende 2 teclados
CALL RegistrarPedido(1, 103, 2);

-- Pedido válido: Carlos vende 1 monitor
CALL RegistrarPedido(2, 102, 1);

-- ERRO: estoque insuficiente (produto 105 só tem 30, pedindo 100)
CALL RegistrarPedido(3, 105, 100);

-- Verificando o estoque atualizado do teclado (era 50, vendeu 2)
SELECT id, nome, estoque FROM produtos WHERE id = 103;

-- Verificando os pedidos criados
SELECT id, id_vendedor, valor_total, status FROM pedidos ORDER BY id DESC LIMIT 3;

Por que usar IN?

Todos os parâmetros desta procedure são entrada: o ID do vendedor, do produto e a quantidade. A procedure processa tudo internamente e retorna o resultado via SELECT. Em um sistema real, essa procedure substituiria dezenas de linhas de código PHP/Java espalhadas pela aplicação.

Passo 4 — Procedure com OUT: Estatísticas do Vendedor

Conceito: O parâmetro OUT devolve valores para a aplicação após a execução. Esta procedure calcula o total de vendas e o ticket médio de um vendedor no mês atual, retornando os resultados em parâmetros de saída. 

DELIMITER //

CREATE PROCEDURE ObterEstatisticasVendedor(
    IN p_id_vendedor INT,
    OUT p_total_vendas DECIMAL(10,2),
    OUT p_total_pedidos INT,
    OUT p_ticket_medio DECIMAL(10,2)
)
BEGIN
    -- Calcula o total de vendas do vendedor no mês atual
    SELECT COALESCE(SUM(valor_total), 0), COUNT(*)
    INTO p_total_vendas, p_total_pedidos
    FROM pedidos
    WHERE id_vendedor = p_id_vendedor
      AND MONTH(data_pedido) = MONTH(CURDATE())
      AND YEAR(data_pedido) = YEAR(CURDATE())
      AND status = 'FINALIZADO';

    -- Calcula o ticket médio
    IF p_total_pedidos > 0 THEN
        SET p_ticket_medio = p_total_vendas / p_total_pedidos;
    ELSE
        SET p_ticket_medio = 0.00;
    END IF;

END //

DELIMITER ;

Testando a Procedure

-- Consultando estatísticas da Ana (vendedor 1)
CALL ObterEstatisticasVendedor(1, @total_ana, @pedidos_ana, @ticket_ana);
SELECT @total_ana AS 'Total Vendas (R$)',
       @pedidos_ana AS 'Total Pedidos',
       @ticket_ana AS 'Ticket Médio (R$)';

-- Consultando estatísticas do Carlos (vendedor 2)
CALL ObterEstatisticasVendedor(2, @total_carlos, @pedidos_carlos, @ticket_carlos);
SELECT @total_carlos AS 'Total Vendas (R$)',
       @pedidos_carlos AS 'Total Pedidos',
       @ticket_carlos AS 'Ticket Médio (R$)';

-- Consultando estatísticas da Maria (vendedor 3 — sem pedidos finalizados)
CALL ObterEstatisticasVendedor(3, @total_maria, @pedidos_maria, @ticket_maria);
SELECT @total_maria AS 'Total Vendas (R$)',
       @pedidos_maria AS 'Total Pedidos',
       @ticket_maria AS 'Ticket Médio (R$)';

Palavra-chave INTO

Dentro da procedure, o comando SELECT ... INTO p_total_vendas, p_total_pedidos atribui os resultados da consulta diretamente aos parâmetros de saída. Fora da procedure, a aplicação lê esses valores usando variáveis de sessão (@total_ana).

Passo 5 — Procedure com INOUT: Aplicar Desconto Progressivo

Conceito: O parâmetro INOUT recebe um valor, pode ser modificado pela procedure e retorna o novo valor. Esta procedure aplica desconto progressivo com base no volume de compras. 

DELIMITER //

CREATE PROCEDURE AplicarDescontoProgressivo(
    INOUT p_valor DECIMAL(10,2),
    IN p_quantidade INT
)
BEGIN
    DECLARE v_percentual DECIMAL(5,2) DEFAULT 0;

    -- Define o percentual de desconto com base na quantidade
    IF p_quantidade >= 10 THEN
        SET v_percentual = 15.00;  -- 15% para 10+ unidades
    ELSEIF p_quantidade >= 5 THEN
        SET v_percentual = 10.00;  -- 10% para 5-9 unidades
    ELSEIF p_quantidade >= 3 THEN
        SET v_percentual = 5.00;   -- 5% para 3-4 unidades
    ELSE
        SET v_percentual = 0.00;   -- Sem desconto para menos de 3
    END IF;

    -- Aplica o desconto no valor de entrada
    SET p_valor = p_valor - (p_valor * v_percentual / 100);

    -- Retorna o desconto aplicado junto com o valor final
    SELECT p_valor AS 'Valor Final (R$)',
           v_percentual AS 'Desconto Aplicado (%)';

END //

DELIMITER ;

Testando a Procedure

-- Teste 1: 12 unidades → 15% de desconto
SET @valor = 350.00;  -- Preço unitário do teclado
CALL AplicarDescontoProgressivo(@valor, 12);
-- Resultado: 350.00 → 297.50 (desconto de 15%)

-- Teste 2: 6 unidades → 10% de desconto

-- Resultado: 450.00 → 405.00 (desconto de 10%)

-- Teste 3: 2 unidades → sem desconto

-- Resultado: 280.00 → 280.00 (sem desconto)

Passo 6 — Function: Calcular Comissão do Vendedor

Conceito: Diferente da procedure, a function sempre retorna um valor via RETURN e pode ser usada diretamente dentro de um SELECT.

Esta função calcula a comissão de um vendedor com base no total de vendas: 5% para quem bateu a meta, 3% para quem não bateu. 

DELIMITER //

CREATE FUNCTION CalcularComissao(id_vend INT) RETURNS DECIMAL(10,2)
BEGIN
    DECLARE v_total_vendas DECIMAL(10,2);
    DECLARE v_meta DECIMAL(10,2);
    DECLARE v_percentual DECIMAL(5,2);

    -- Busca o total de vendas finalizadas no mês
    SELECT COALESCE(SUM(valor_total), 0) INTO v_total_vendas
    FROM pedidos
    WHERE id_vendedor = id_vend
      AND MONTH(data_pedido) = MONTH(CURDATE())
      AND YEAR(data_pedido) = YEAR(CURDATE())
      AND status = 'FINALIZADO';

    -- Busca a meta mensal do vendedor
    SELECT meta_mensal INTO v_meta
    FROM vendedores
    WHERE id = id_vend;

    -- Define o percentual com base no desempenho
    IF v_total_vendas >= v_meta THEN
        SET v_percentual = 5.00;  -- Bateu a meta: 5%
    ELSE
        SET v_percentual = 3.00;  -- Não bateu: 3%
    END IF;

    RETURN v_total_vendas * v_percentual / 100;

END //

DELIMITER ;

Testando a Function

-- A function pode ser usada diretamente dentro de um SELECT
SELECT 
    v.id,
    v.nome,
    v.meta_mensal AS 'Meta (R$)',
    (SELECT COALESCE(SUM(valor_total), 0) 
     FROM pedidos 
     WHERE id_vendedor = v.id 
       AND status = 'FINALIZADO'
       AND MONTH(data_pedido) = MONTH(CURDATE())) AS 'Vendas (R$)',
    CalcularComissao(v.id) AS 'Comissão (R$)'
FROM vendedores v
ORDER BY v.id;

Procedure vs Function — na prática

Note que a function CalcularComissao é chamada dentro do SELECT, algo impossível com uma procedure. Para tarefas que precisam modificar dados ou retornar múltiplos valores, use procedure. Para cálculos escalar, use function.

Passo 7 — Procedure Complexa: Fechamento Mensal de Comissões

Conceito: Uma procedure real em produção geralmente combina múltiplas operações: consultas, cálculos condicionais, inserções e atualizações — tudo em uma única chamada.

Esta procedure simula o fechamento mensal: percorre todos os vendedores, calcula a comissão de cada um e registra na tabela comissoes. 

DELIMITER //

CREATE PROCEDURE FechamentoMensalComissoes(IN p_mes_ano VARCHAR(7))
BEGIN
    DECLARE v_id INT;
    DECLARE v_nome VARCHAR(100);
    DECLARE v_total DECIMAL(10,2);
    DECLARE v_meta DECIMAL(10,2);
    DECLARE v_percentual DECIMAL(5,2);
    DECLARE v_comissao DECIMAL(10,2);
    DECLARE v_fim INT DEFAULT 0;

    -- Cursor para percorrer todos os vendedores
    DECLARE cur_vendedores CURSOR FOR
        SELECT id, nome, meta_mensal FROM vendedores ORDER BY id;

    -- Handler para detectar o fim do cursor
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_fim = 1;

    OPEN cur_vendedores;

    loop_vendedores: LOOP
        FETCH cur_vendedores INTO v_id, v_nome, v_meta;
        IF v_fim = 1 THEN
            LEAVE loop_vendedores;
        END IF;

        -- Calcula total de vendas finalizadas do vendedor no mês
        SELECT COALESCE(SUM(valor_total), 0) INTO v_total
        FROM pedidos
        WHERE id_vendedor = v_id
          AND DATE_FORMAT(data_pedido, '%Y-%m') = p_mes_ano
          AND status = 'FINALIZADO';

        -- Define percentual de comissão
        IF v_total >= v_meta THEN
            SET v_percentual = 5.00;
        ELSE
            SET v_percentual = 3.00;
        END IF;

        SET v_comissao = v_total * v_percentual / 100;

        -- Registra na tabela de comissões (só se houver vendas)
        IF v_total > 0 THEN
            INSERT INTO comissoes (id_vendedor, mes_ano, total_vendas, percentual_comissao, valor_comissao)
            VALUES (v_id, p_mes_ano, v_total, v_percentual, v_comissao);
        END IF;

    END LOOP;

    CLOSE cur_vendedores;

    -- Retorna o resumo do fechamento
    SELECT 
        v.nome AS 'Vendedor',
        c.total_vendas AS 'Total Vendas (R$)',
        c.percentual_comissao AS 'Comissão (%)',
        c.valor_comissao AS 'Valor Comissão (R$)'
    FROM comissoes c
    INNER JOIN vendedores v ON c.id_vendedor = v.id
    WHERE c.mes_ano = p_mes_ano
    ORDER BY c.valor_comissao DESC;

END //

DELIMITER ;

Testando a Procedure

-- Executa o fechamento de maio/2026
CALL FechamentoMensalComissoes('2026-05');

-- Verificando o registro completo na tabela de comissões
SELECT * FROM comissoes ORDER BY id;

Bônus: Como Remover e Listar

Para gerenciar os programas armazenados no banco: 

-- Listar todas as procedures do banco atual
SELECT routine_name, routine_type, routine_definition
FROM information_schema.routines
WHERE routine_schema = DATABASE()
  AND routine_type IN ('PROCEDURE', 'FUNCTION');

-- Remover uma procedure específica
DROP PROCEDURE IF EXISTS RegistrarPedido;

-- Remover uma function específica
DROP FUNCTION IF EXISTS CalcularComissao;

Dicas & Lembretes

  • DELIMITER: No MySQL, sempre use DELIMITER // antes de criar procedures/functions com múltiplas linhas. Sem ele, o ";" interno corta o comando antes do bloco terminar.
  • Variáveis de sessão: Para ler parâmetros OUT, use @variavel antes do CALL e depois do CALL. As variáveis com "@" são mantidas durante toda a sessão.
  • Cursor e Handler: Em procedures complexas (como o FechamentoMensal), o CURSOR percorre linhas de uma consulta e o CONTINUE HANDLER trata o fim dos dados sem erro.
  • Recompila: Se precisar alterar uma procedure, use DROP PROCEDURE antes de CREATE PROCEDURE com o mesmo nome, ou use CREATE OR REPLACE (MySQL 8.0+).
