Enunciado

Você foi contratado(a) para automatizar as regras de negócio da loja VendaMais. Em vez de deixar a aplicação executar comandos SQL soltos, todas as operações de venda, estoque e estatísticas devem ser encapsuladas em Stored Procedures no servidor MySQL.

Seu objetivo é criar as procedures e funções descritas nos desafios, executá-las e validar os resultados diretamente no banco.

Preparação

  1. Ambiente: Abra seu terminal ou o MySQL Workbench e conecte-se ao seu servidor local.
  2. Script: Execute o script da seção "1. Script de Preparação" integralmente e confirme que o banco vendamais_db foi criado.
  3. Resolução: Escreva cada procedure/função com o comando DELIMITER // e DELIMITER ; ao final, como no exemplo da aula.
  4. Validação: Depois de cada CALL, consulte as tabelas para confirmar que os dados foram alterados conforme o esperado.

1. Script de Preparação (MySQL)

Execute o script abaixo para criar o banco, as tabelas e a massa de dados do cenário de vendas:

CREATE DATABASE vendamais_db;
USE vendamais_db;

CREATE TABLE vendedores (
    codigo_vendedor INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    salario_fixo DECIMAL(10,2) NOT NULL
);

CREATE TABLE produtos (
    codigo INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco_venda DECIMAL(10,2) NOT NULL,
    saldo_estoque INT NOT NULL DEFAULT 0
);

CREATE TABLE pedidos (
    numero_pedido INT AUTO_INCREMENT PRIMARY KEY,
    data_pedido DATE NOT NULL,
    codigo_vendedor INT NOT NULL,
    FOREIGN KEY (codigo_vendedor) REFERENCES vendedores(codigo_vendedor)
);

CREATE TABLE itens_pedido (
    numero_pedido INT NOT NULL,
    codigo_produto INT NOT NULL,
    quantidade INT NOT NULL,
    preco_unitario DECIMAL(10,2) NOT NULL,
    PRIMARY KEY (numero_pedido, codigo_produto),
    FOREIGN KEY (numero_pedido) REFERENCES pedidos(numero_pedido),
    FOREIGN KEY (codigo_produto) REFERENCES produtos(codigo)
);

2. Desafios de Prática

Bloco 1: Procedure básica de estoque

  1. Crie a procedure AtualizarEstoque que recebe um IN codigo_produto e um IN qtd, e decrementa o saldo_estoque do produto correspondente.
  2. Chame AtualizarEstoque(1, 1) e verifique que o saldo do produto 1 passou de 10 para 9.
  3. Reflita: por que a procedure é mais segura do que um UPDATE executado diretamente pela aplicação?

Bloco 2: Procedure que registra uma venda completa

Crie uma procedure que encapsula todo o processo de venda: insere um novo pedido, insere o item e dá baixa no estoque — tudo em uma única chamada.

  1. Crie a procedure RegistrarVenda com parâmetros: IN id_vendedor INT, IN codigo_produto INT, IN qtd INT. Dentro dela:
    • Insira um registro em pedidos usando NOW() como data (ou CURDATE()).
    • Insira o item em itens_pedido, capturando o numero_pedido recém-criado (dica: LAST_INSERT_ID()).
    • Dê baixa no estoque do produto.
  2. Chame CALL RegistrarVenda(3, 2, 2) (vendedora Fernanda vende 2 Monitores).
  3. Valide: o estoque do Monitor deve cair de 15 para 13, e o faturamento de Fernanda deve aumentar em 1.799,80 (2 × 899,90).

Bloco 3: Parâmetro OUT (saída)

  1. Crie a procedure ObterTotalPedidosVendedor com IN id_vendedor INT e OUT total INT, que atribui ao parâmetro de saída o total de pedidos do vendedor (use SELECT COUNT(*) INTO ...).
  2. Invoque e exiba o resultado: 
    CALL ObterTotalPedidosVendedor(1, @total);
SELECT @total;
  3. Crie ObterFaturamentoVendedor com OUT faturamento DECIMAL(10,2), somando preco_unitario * quantidade dos itens dos pedidos daquele vendedor (use um JOIN).
  4. Invoque para o vendedor 1 e confira se o valor corresponde ao total somado manualmente.

Bloco 4: Parâmetro INOUT (entrada e saída)

  1. Crie a procedure AplicarAumentoSalario com INOUT salario DECIMAL(10,2) e IN percentual DECIMAL(5,2), que aumenta o valor do parâmetro no percentual informado.
  2. Teste com o salário do vendedor 2 (Mariana, 3200.00): 
    SET @salario = (SELECT salario_fixo FROM vendedores WHERE codigo_vendedor = 2);
CALL AplicarAumentoSalario(@salario, 10);
SELECT @salario; -- deve exibir 3520.00

UPDATE vendedores SET salario_fixo = @salario WHERE codigo_vendedor = 2;
  3. Explique com suas palavras a diferença entre OUT e INOUT a partir do que observou.

Orientações Finais

  • Delimitador: No MySQL, toda procedure de múltiplas linhas precisa ser criada entre DELIMITER // e DELIMITER ;.
  • Privilégios: Você precisa do privilégio CREATE ROUTINE para criar e EXECUTE para chamar as procedures.
  • Validação: Sempre confirme os efeitos colaterais (estoque, totais) com um SELECT após cada CALL.
  • Variáveis: Para receber valores de saída, use variáveis de usuário com @ (ex.: @total).
  • Tente sozinho: Resolva os blocos sem consultar a aula primeiro; volte a ela somente se travar em algum conceito.
