Teoria & Conceitos

1. O que é uma Stored Function?

Uma Stored Function (Função Armazenada) é um conjunto de instruções SQL definido pelo usuário, armazenado no servidor, que realiza uma tarefa ou cálculo e obrigatoriamente retorna um único valor. Diferente dos procedimentos, que são invocados pelo comando CALL, as funções são chamadas diretamente dentro de comandos SELECT, WHERE ou UPDATE, integrando-se perfeitamente às expressões do banco de dados.

Principais Vantagens

  • Simplificação de Aplicações: Escreve-se o código do cálculo uma vez e o invoca sempre que necessário, evitando a repetição de fórmulas complexas no código da aplicação.
  • Poder Algorítmico: Permitem o uso de estruturas condicionais (IF, CASE) e laços de repetição (WHILE, LOOP) que não seriam possíveis em uma consulta SQL simples.
  • Desempenho: No PostgreSQL, funções escritas em SQL puro podem ser "otimizadas" pelo planejador de consultas, permitindo o uso de índices e melhorando a performance.

2. Diferença entre Function e Procedure

Embora ambos sejam "programas armazenados", suas aplicações diferem:

Aspecto Function Procedure
Retorno Deve retornar um valor via cláusula RETURN. Não retorna um valor diretamente (embora possa usar parâmetros OUT).
Invocação Usada em expressões (ex: SELECT soma(a, b)). Invocada via CALL.
Resultados Sempre um único valor escalar. Pode retornar múltiplos conjuntos de resultados ou apenas realizar alterações no banco.

Implementação no MySQL

No MySQL, a criação de funções exige a definição do tipo de retorno e de características como a determinística (se a função sempre retorna o mesmo resultado para os mesmos parâmetros).

Exemplo Prático: Capitalização de Texto

Este exemplo cria uma função que coloca a primeira letra de uma string em maiúsculo: 

DELIMITER $$

CREATE FUNCTION iniciais_maiusculas (s VARCHAR(255))
RETURNS VARCHAR(255) DETERMINISTIC
BEGIN
    RETURN CONCAT(UPPER(LEFT(s, 1)), MID(s, 2));
END $$

DELIMITER ;

-- Como utilizar em uma consulta
SELECT nome_cliente, iniciais_maiusculas(nome_cliente) FROM cliente;

Observação Técnica

O uso do comando DELIMITER é essencial no cliente de linha de comando para que o ; interno do corpo da função não seja interpretado como o fim do comando de criação.

Implementação no PostgreSQL

O PostgreSQL é extremamente flexível, permitindo funções escritas em SQL, PL/pgSQL, C, Python e até JavaScript. Além disso, introduz o conceito de Volatilidade para ajudar o otimizador.

Níveis de Volatilidade no PostgreSQL

Nível Descrição
VOLATILE O valor pode mudar a cada chamada (ex: random()). Sempre recomputada.
STABLE O valor é constante dentro de uma mesma consulta para os mesmos argumentos.
IMMUTABLE O valor é sempre o mesmo para os mesmos argumentos (ideal para cálculos matemáticos fixos).

Exemplo Prático: Inserção com Retorno (SQL puro)

CREATE OR REPLACE FUNCTION insere_log (usuario_nome VARCHAR, desc_texto TEXT)
RETURNS INTEGER AS $$
    INSERT INTO logs (user_name, description)
    VALUES (usuario_nome, desc_texto)
    RETURNING log_id;
$$ LANGUAGE SQL VOLATILE;

-- Como utilizar
SELECT insere_log('felipe', 'Acesso ao sistema');

Segurança e Privilégios

O gerenciamento de acesso às funções é vital para a integridade do sistema:

  • GRANT EXECUTE: Concede a um usuário ou papel (role) a permissão de rodar a função.
  • SECURITY DEFINER: No PostgreSQL, permite que a função seja executada com os privilégios de quem a criou, e não de quem a está chamando. É útil para permitir que usuários comuns alterem tabelas específicas através da função sem terem acesso direto à tabela.
-- Concede o direito de executar a função a um papel
GRANT EXECUTE ON FUNCTION insere_log(VARCHAR, TEXT) TO usuario_aplicacao;

-- Executa a função com os privilégios de quem a criou (não de quem chama)
CREATE OR REPLACE FUNCTION atualiza_saldo(conta_id INT, valor DECIMAL(10,2))
RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
    UPDATE contas SET saldo = saldo + valor WHERE id = conta_id;
END;
$$;

Dicas & Lembretes

  • Atomicidade: Toda função deve ter ao menos um comando RETURN.
  • Parâmetros: No MySQL, parâmetros de funções são apenas de entrada (IN), ao contrário dos procedimentos que aceitam OUT e INOUT.
  • Binary Logging: Em servidores MySQL com log binário ativo, é necessário ter o privilégio SUPER e declarar a função como DETERMINISTIC ou que não modifica dados (READS SQL DATA) para garantir a segurança da replicação.

Como aplicar na Prática

  • Formatação de dados: Centralize regras de formatação (máscaras de CPF, capitalização de nomes, telas) em funções reutilizáveis em qualquer consulta.
  • Cálculos de negócio: Encapsule fórmulas como imposto, comissão e desconto em funções IMMUTABLE no PostgreSQL, permitindo que o otimizador as pré-calcule.
  • Validações em cascata: Use funções dentro de WHERE e CHECK para garantir que a mesma regra seja aplicada em qualquer camada do sistema.
  • Auditoria segura: Combine SECURITY DEFINER com GRANT EXECUTE para expor operações controladas sem liberar acesso às tabelas base.
