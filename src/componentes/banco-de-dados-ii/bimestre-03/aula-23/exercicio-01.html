Enunciado

Você foi contratado(a) para centralizar as regras de cálculo e formatação da empresa Clínica Vida. Em vez de a aplicação repetir fórmulas e validações, todas devem ser encapsuladas em Stored Functions e invocadas dentro das consultas.

Seu objetivo é criar funções no MySQL e no PostgreSQL, executá-las dentro de SELECT e entender os conceitos de determinismo, volatilidade e privilégios.

Preparação

  1. Ambiente MySQL: Abra seu terminal ou o MySQL Workbench e execute o script de preparação abaixo.
  2. Ambiente PostgreSQL: Se disponível, abra o psql ou o pgAdmin para os blocos específicos da linguagem PL/pgSQL.
  3. Resolução: Crie cada função com DELIMITER $$ e DELIMITER ; no MySQL, ou com $$ e LANGUAGE plpgsql no PostgreSQL.
  4. Validação: Chame as funções dentro de consultas e confira os valores retornados.

1. Script de Preparação

Execute o script abaixo para criar o banco e a massa de dados do cenário:

-- MySQL
CREATE DATABASE clinica_vida_db;
USE clinica_vida_db;

CREATE TABLE cliente (
    codigo INT AUTO_INCREMENT PRIMARY KEY,
    nome_cliente VARCHAR(100) NOT NULL,
    data_nascimento DATE NOT NULL
);

CREATE TABLE consultas (
    id_consulta INT AUTO_INCREMENT PRIMARY KEY,
    codigo_cliente INT NOT NULL,
    valor_consulta DECIMAL(10,2) NOT NULL,
    data_consulta DATE NOT NULL,
    FOREIGN KEY (codigo_cliente) REFERENCES cliente(codigo)
);

INSERT INTO cliente (nome_cliente, data_nascimento) VALUES
('maria da silva', '1990-05-12'),
('joao pereira', '2001-11-03'),
('ana souza', '1985-02-27');

INSERT INTO consultas (codigo_cliente, valor_consulta, data_consulta) VALUES
(1, 200.00, '2026-03-10'),
(1, 250.00, '2026-04-15'),
(2, 180.00, '2026-04-20'),
(3, 300.00, '2026-05-02');

2. Desafios de Prática

Bloco 1: Função de formatação de texto (MySQL)

  1. Crie a função iniciais_maiusculas(s VARCHAR(255)) que retorna uma VARCHAR(255) DETERMINISTIC e coloca a primeira letra da string em maiúsculo (use UPPER, LEFT e MID, como no exemplo da aula).
  2. Use a função para exibir os nomes dos clientes formatados: 
    SELECT nome_cliente, iniciais_maiusculas(nome_cliente) FROM cliente;
  3. Explique por que essa função foi declarada como DETERMINISTIC.

Bloco 2: Função de cálculo de negócio (MySQL)

  1. Crie a função CalcularDesconto(valor DECIMAL(10,2), percentual DECIMAL(5,2)) que retorna o valor com o desconto aplicado.
  2. Crie a função CalcularIdade(data_nascimento DATE) que retorna a idade da pessoa em anos (dica: use TIMESTAMPDIFF(YEAR, ...) ou a lógica que preferir).
  3. Utilize as funções dentro de uma única consulta que mostre: nome, idade e valor da última consulta de cada cliente com 10% de desconto. 
    SELECT
    iniciais_maiusculas(c.nome_cliente) AS nome,
    CalcularIdade(c.data_nascimento) AS idade,
    CalcularDesconto(MAX(con.valor_consulta), 10) AS valor_com_desconto
FROM cliente c
JOIN consultas con ON con.codigo_cliente = c.codigo
GROUP BY c.codigo;
  4. Justifique por que funções podem ser usadas dentro de SELECT, mas procedures não.

Bloco 3: Funções no PostgreSQL e volatilidade

Execute os desafios abaixo no PostgreSQL (PL/pgSQL ou SQL puro):

  1. Crie a função soma_dois(a INT, b INT) em SQL puro que retorna a soma, e declare-a como IMMUTABLE. Explique o motivo dessa classificação.
  2. Crie a função agora_no_banco() que retorna CURRENT_TIMESTAMP e classifique-a corretamente entre VOLATILE, STABLE e IMMUTABLE. Justifique.
  3. Crie uma função em SQL puro chamada insere_log(usuario_nome VARCHAR, desc_texto TEXT) que insere um registro em uma tabela logs e retorna o log_id gerado (use a cláusula RETURNING, como no exemplo da aula).

Bloco 4: Segurança e privilégios (PostgreSQL)

  1. Crie a função atualiza_saldo(conta_id INT, valor DECIMAL(10,2)) que atualiza o saldo de uma tabela contas e não retorna valor (RETURNS VOID), declarada com SECURITY DEFINER.
  2. Conceda permissão de execução ao papel da aplicação: 
    GRANT EXECUTE ON FUNCTION atualiza_saldo(INT, DECIMAL(10,2)) TO usuario_aplicacao;
  3. Explique, com suas palavras, a diferença prática entre SECURITY DEFINER e o comportamento padrão SECURITY INVOKER.

Orientações Finais

  • Retorno: Toda função deve ter ao menos um comando RETURN.
  • Parâmetros: No MySQL, os parâmetros de funções são apenas de entrada (IN), ao contrário dos procedimentos.
  • Determinismo: Em servidores MySQL com log binário ativo, declare funções como DETERMINISTIC ou que não modifiquem dados.
  • Volatilidade: Classifique corretamente as funções PostgreSQL para ajudar o otimizador de consultas.
  • Tente sozinho: Resolva os blocos sem consultar a aula primeiro; volte a ela somente se travar em algum conceito.
