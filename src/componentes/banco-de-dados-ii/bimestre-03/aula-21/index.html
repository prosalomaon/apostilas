Teoria & Conceitos

1. O que são Blocos SQL?

Um bloco SQL é um agrupamento de múltiplas instruções que o Sistema Gerenciador de Banco de Dados (SGBD) trata como uma única unidade lógica. Eles formam o "corpo" de objetos como Procedimentos Armazenados (Stored Procedures), Funções e Gatilhos (Triggers).

2. Estrutura Fundamental: BEGIN ... END

A sintaxe básica de um bloco é delimitada pelas palavras-chave BEGIN para iniciar e END para finalizar.

  • Terminadores Internos: Cada comando individual dentro do bloco deve ser finalizado com ponto e vírgula (;).
  • Variáveis Locais: Blocos permitem o uso da instrução DECLARE para criar variáveis que existem apenas durante a execução daquele trecho de código.

3. Controle de Fluxo e Lógica Procedural

Diferente das consultas simples, os blocos permitem a implementação de lógica algorítmica:

A. Condicionais (IF e CASE)

Permitem que o banco de dados tome decisões baseadas em valores de dados.

-- Sintaxe Conceitual
IF condicao THEN
    -- comandos se verdadeiro;
ELSE
    -- comandos se falso;
END IF;

B. Laços de Repetição (Loops)

Utilizados para repetir operações até que uma condição de parada seja atingida. As formas mais comuns incluem WHILE, REPEAT e LOOP simples. Eles são frequentemente usados com Cursores para processar resultados linha por linha.

No MySQL, os laços são escritos dentro de um bloco BEGIN ... END e exigem o uso do DELIMITER. O exemplo abaixo preenche uma tabela auxiliar de sorteio usando as três formas mais comuns: 

CREATE TABLE numeros_sorteio (id INT AUTO_INCREMENT PRIMARY KEY, valor INT);

DELIMITER $$

-- WHILE: executa enquanto a condição for verdadeira
CREATE PROCEDURE GeraSorteioWhile(IN qtd INT)
BEGIN
    DECLARE contador INT DEFAULT 1;

    WHILE contador <= qtd DO
        INSERT INTO numeros_sorteio (valor) VALUES (contador);
        SET contador = contador + 1;
    END WHILE;
END $$

-- REPEAT: executa primeiro e repete até a condição se tornar verdadeira
CREATE PROCEDURE GeraSorteioRepeat(IN qtd INT)
BEGIN
    DECLARE contador INT DEFAULT 1;

    REPEAT
        INSERT INTO numeros_sorteio (valor) VALUES (contador);
        SET contador = contador + 1;
    UNTIL contador > qtd
    END REPEAT;
END $$

-- LOOP: infinito, interrompido por um LEAVE rotulado
CREATE PROCEDURE GeraSorteioLoop(IN qtd INT)
BEGIN
    DECLARE contador INT DEFAULT 1;

    loop_sorteio: LOOP
        INSERT INTO numeros_sorteio (valor) VALUES (contador);
        SET contador = contador + 1;

        IF contador > qtd THEN
            LEAVE loop_sorteio;
        END IF;
    END LOOP;
END $$

DELIMITER ;

CALL GeraSorteioWhile(10);
CALL GeraSorteioRepeat(20);
CALL GeraSorteioLoop(30);

SELECT COUNT(*) FROM numeros_sorteio; -- 60 números

No PostgreSQL (PL/pgSQL), a forma mais comum é o laço FOR, que percorre uma faixa de valores ou o resultado de uma consulta — ideal para processar linhas uma a uma: 

-- Laço FOR percorrendo uma faixa de valores
CREATE OR REPLACE FUNCTION gera_sorteio_for(qtd INT) RETURNS VOID AS $$
DECLARE
    contador INT;
BEGIN
    FOR contador IN 1..qtd LOOP
        INSERT INTO numeros_sorteio (valor) VALUES (contador);
    END LOOP;
END;
$$ LANGUAGE plpgsql;

SELECT gera_sorteio_for(40);

-- Laço FOR percorrendo o resultado de uma consulta (linha por linha)
CREATE OR REPLACE FUNCTION soma_estoque() RETURNS INT AS $$
DECLARE
    linha RECORD;
    total INT := 0;
BEGIN
    FOR linha IN SELECT saldo_estoque FROM produtos LOOP
        total := total + linha.saldo_estoque;
    END LOOP;
    RETURN total;
END;
$$ LANGUAGE plpgsql;

SELECT soma_estoque();

B1. Laços com Cursores

Quando a repetição precisa percorrer as linhas do resultado de uma consulta, combinamos um laço com um Cursor: um ponteiro que percorre o conjunto de resultados linha por linha. Em um cursor são executadas quatro etapas: DECLARE (definição da consulta), OPEN (abertura), FETCH (leitura de cada linha) e CLOSE (liberação dos recursos). 

-- MySQL: cursor com laço LOOP e handler para detectar o fim dos dados
DELIMITER $$

CREATE PROCEDURE AtualizaComissoes()
BEGIN
    DECLARE done INT DEFAULT FALSE;
    DECLARE v_codigo INT;
    DECLARE v_salario DECIMAL(10,2);

    DECLARE cursor_vendedores CURSOR FOR
        SELECT codigo_vendedor, salario_fixo FROM vendedores;

    -- Quando o FETCH não encontrar mais linhas, marca o fim da leitura
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;

    OPEN cursor_vendedores;

    loop_leitura: LOOP
        FETCH cursor_vendedores INTO v_codigo, v_salario;

        IF done THEN
            LEAVE loop_leitura;
        END IF;

        IF v_salario < 2000 THEN
            UPDATE vendedores
            SET salario_fixo = salario_fixo * 1.05
            WHERE codigo_vendedor = v_codigo;
        END IF;
    END LOOP;

    CLOSE cursor_vendedores;
END $$

DELIMITER ;

CALL AtualizaComissoes();

No PostgreSQL, o cursor é declarado na seção DECLARE da função, e o laço LOOP usa o comando EXIT WHEN NOT FOUND para encerrar quando todas as linhas forem percorridas: 

CREATE OR REPLACE FUNCTION atualiza_comissoes() RETURNS VOID AS $$
DECLARE
    rec_vendedor RECORD;
    cursor_vendedores CURSOR FOR
        SELECT codigo_vendedor, salario_fixo FROM vendedores;
BEGIN
    OPEN cursor_vendedores;

    LOOP
        FETCH cursor_vendedores INTO rec_vendedor;
        EXIT WHEN NOT FOUND;

        IF rec_vendedor.salario_fixo < 2000 THEN
            UPDATE vendedores
            SET salario_fixo = salario_fixo * 1.05
            WHERE codigo_vendedor = rec_vendedor.codigo_vendedor;
        END IF;
    END LOOP;

    CLOSE cursor_vendedores;
END;
$$ LANGUAGE plpgsql;

SELECT atualiza_comissoes();

4. Implementação Prática: MySQL vs. PostgreSQL

Cada SGBD possui particularidades na forma como implementa e executa blocos de linguagem procedural:

Aspecto MySQL PostgreSQL (PL/pgSQL)
Linguagem procedural SQL procedural nativo PL/pgSQL (linguagem própria)
Declaração de variáveis DECLARE dentro do BEGIN DECLARE antes do BEGIN
Delimitador de bloco Requer DELIMITER $$ no terminal Usa $$ como delimitador de string literal
Criação de Procedure CREATE PROCEDURE nome() CREATE OR REPLACE FUNCTION nome() RETURNS tipo

5. Tratamento de Exceções

Blocos SQL podem conter Manipuladores de Condição (Condition Handlers). Eles funcionam como um "escudo" que captura erros — como uma violação de chave estrangeira — e decide o que fazer: ignorar o erro, desfazer a operação (ROLLBACK) ou emitir um aviso customizado via comando SIGNAL.

No MySQL, os manipuladores são declarados com a instrução DECLARE ... HANDLER no início do bloco. Existem dois tipos principais: CONTINUE, que ignora o erro e segue o fluxo, e EXIT, que encerra o bloco. O comando SIGNAL permite emitir um erro customizado para a aplicação: 

DELIMITER $$

CREATE PROCEDURE RegistraPedido(IN id_vendedor INT, IN id_produto INT)
BEGIN
    -- EXIT: se qualquer erro ocorrer, desfaz a transação e aborta com mensagem própria
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Erro ao registrar o pedido';
    END;

    -- CONTINUE: ignora duplicatas (SQLSTATE 23000) e segue o fluxo normal
    DECLARE CONTINUE HANDLER FOR SQLSTATE '23000' SET @ignorada = 1;

    START TRANSACTION;

    INSERT INTO pedido (codigo_vendedor) VALUES (id_vendedor);
    INSERT INTO item_pedido (numero_pedido, codigo_produto, quantidade, preco_unitario)
    VALUES (LAST_INSERT_ID(), id_produto, 1,
            (SELECT preco_venda FROM produtos WHERE codigo = id_produto));

    COMMIT;
END $$

DELIMITER ;

CALL RegistraPedido(11, 108);

No PostgreSQL, o tratamento é feito em um sub-bloco com a cláusula EXCEPTION WHEN ... THEN. Cada exceção tem um nome próprio, como foreign_key_violation ou unique_violation: 

CREATE OR REPLACE FUNCTION registra_pedido(id_vendedor INT, id_produto INT) RETURNS VOID AS $$
BEGIN
    BEGIN
        INSERT INTO pedido (codigo_vendedor) VALUES (id_vendedor);
        INSERT INTO item_pedido (numero_pedido, codigo_produto, quantidade, preco_unitario)
        VALUES (LASTVAL(), id_produto, 1,
                (SELECT preco_venda FROM produtos WHERE codigo = id_produto));

        EXCEPTION WHEN foreign_key_violation THEN
            RAISE NOTICE 'Vendedor ou produto inexistente';
            ROLLBACK;
    END;
END;
$$ LANGUAGE plpgsql;

SELECT registra_pedido(11, 108);   -- executa normalmente
SELECT registra_pedido(999, 108);  -- dispara o aviso e desfaz a operação

Exemplo de Código

Abaixo, apresentamos exemplos práticos comparando as sintaxes entre os dois ambientes.

Exemplo no MySQL

No MySQL, ao definir blocos via terminal, você deve usar o comando DELIMITER para evitar que o cliente interprete os ; internos como o fim do comando de criação do objeto.

Criação da Procedure

DELIMITER $$

CREATE PROCEDURE CalculaBonus(IN id_vendedor INT)
BEGIN
    DECLARE salario_atual DECIMAL(10,2);
    SET salario_atual = (SELECT salario_fixo FROM vendedores WHERE codigo_vendedor = id_vendedor);
    
    IF salario_atual < 2000 THEN
        UPDATE vendedores SET salario_fixo = salario_fixo * 1.1 WHERE codigo_vendedor = id_vendedor;
    END IF;
END $$

DELIMITER ;

Como utilizar

Após criada, uma Stored Procedure no MySQL é invocada com o comando CALL, passando os argumentos necessários. 

-- Chama a procedure para o vendedor de código 5
CALL CalculaBonus(5);

-- Verifica o resultado após a execução
SELECT codigo_vendedor, salario_fixo FROM vendedores WHERE codigo_vendedor = 5;

Exemplo no PostgreSQL (PL/pgSQL)

No PostgreSQL, os blocos de lógica são escritos na linguagem PL/pgSQL. A seção de declaração de variáveis (DECLARE) ocorre obrigatoriamente antes do BEGIN.

Criação da Function

CREATE OR REPLACE FUNCTION aumenta_estoque(prod_id INT, qtd INT) RETURNS VOID AS $$
DECLARE
    estoque_atual INT;
BEGIN
    SELECT saldo_estoque INTO estoque_atual FROM produtos WHERE codigo = prod_id;
    UPDATE produtos SET saldo_estoque = estoque_atual + qtd WHERE codigo = prod_id;
END;
$$ LANGUAGE plpgsql;

Como utilizar

No PostgreSQL, funções que retornam VOID são chamadas com SELECT ou com o atalho PERFORM (dentro de outro bloco). Funções com retorno de valor podem ser usadas diretamente em consultas. 

-- Chama a função para adicionar 50 unidades ao produto de código 10
SELECT aumenta_estoque(10, 50);

-- Verifica o resultado após a execução
SELECT codigo, saldo_estoque FROM produtos WHERE codigo = 10;

-- Chamando PERFORM dentro de outro bloco PL/pgSQL
DO $$
BEGIN
    PERFORM aumenta_estoque(10, 50);
END;
$$;

Dicas & Lembretes

  • Atomicidade: Embora um bloco contenha muitos comandos, ele é disparado como uma unidade. Se um erro ocorrer e não for tratado, ele pode interromper todo o processo.
  • Performance: Use blocos para reduzir o tráfego de rede entre a aplicação e o banco, executando a lógica diretamente onde os dados residem.
  • Identação: Mantenha o código dentro do BEGIN...END identado para facilitar a leitura de estruturas aninhadas.
  • Limpeza: Se abrir um CURSOR dentro de um bloco, lembre-se sempre de dar um CLOSE antes do END para liberar recursos do servidor.
