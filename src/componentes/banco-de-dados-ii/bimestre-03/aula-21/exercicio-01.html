Enunciado

Você foi contratado(a) para implementar rotinas de lógica procedural no banco de dados da empresa Núcleo Dados. Em vez de a aplicação executar vários comandos SQL soltos, toda a regra deve ser encapsulada em blocos SQL no servidor MySQL.

Seu objetivo é criar procedures com variáveis locais, condicionais, laços de repetição, cursores e manipuladores de condição, executá-las e validar os resultados diretamente no banco.

Preparação

  1. Ambiente: Abra seu terminal ou o MySQL Workbench e conecte-se ao seu servidor local.
  2. Script: Execute o script da seção "1. Script de Preparação" integralmente e confirme que o banco nucleo_dados_db foi criado.
  3. Resolução: Escreva cada procedure com DELIMITER $$ e DELIMITER ; ao final, como nos exemplos da aula.
  4. Validação: Depois de cada CALL, consulte as tabelas para confirmar que os dados foram alterados conforme o esperado.

1. Script de Preparação (MySQL)

Execute o script abaixo para criar o banco, as tabelas e a massa de dados do cenário:

CREATE DATABASE nucleo_dados_db;
USE nucleo_dados_db;

CREATE TABLE vendedores (
    codigo_vendedor INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    salario_fixo DECIMAL(10,2) NOT NULL
);

CREATE TABLE numeros_sorteio (
    id INT AUTO_INCREMENT PRIMARY KEY,
    valor INT
);

CREATE TABLE vendedores_auditoria (
    id INT AUTO_INCREMENT PRIMARY KEY,
    codigo_vendedor INT NOT NULL,
    salario_anterior DECIMAL(10,2),
    salario_novo DECIMAL(10,2),
    data_registro DATETIME DEFAULT NOW()
);

INSERT INTO vendedores (nome, salario_fixo) VALUES
('Carlos Souza', 1800.00),
('Mariana Lima', 2500.00),
('Fernanda Alves', 3200.00);

2. Desafios de Prática

Bloco 1: Variáveis locais e condicional IF

  1. Crie a procedure CalculaBonus com um parâmetro IN id_vendedor INT. Dentro de um bloco BEGIN ... END:
    • Declare uma variável local salario_atual DECIMAL(10,2).
    • Atribua a ela o salario_fixo do vendedor (use SET salario_atual = (SELECT ...)).
    • Se o salário for menor que 2000, aplique um reajuste de 10%; caso contrário, aplique 5%.
  2. Chame CALL CalculaBonus(1) e confirme que o salário do vendedor Carlos passou de 1800.00 para 1980.00.
  3. Explique por que a variável salario_atual existe apenas durante a execução da procedure.

Bloco 2: Laços de repetição

Crie três procedures que preenchem a tabela numeros_sorteio com a sequência de 1 até a quantidade informada, usando cada uma das formas de laço:

  1. GeraSorteioWhile(IN qtd INT) usando WHILE ... DO ... END WHILE.
  2. GeraSorteioRepeat(IN qtd INT) usando REPEAT ... UNTIL ... END REPEAT.
  3. GeraSorteioLoop(IN qtd INT) usando LOOP ... END LOOP com um rótulo e a instrução LEAVE para interromper.

Chame cada uma com 10 e valide com SELECT COUNT(*) FROM numeros_sorteio;.

Bloco 3: Cursor para processar linha por linha

  1. Crie a procedure AtualizaSalarios que:
    • Declara um cursor que percorre codigo_vendedor e salario_fixo de vendedores.
    • Declara um manipulador CONTINUE HANDLER FOR NOT FOUND para detectar o fim da leitura.
    • Executa as etapas do cursor: OPEN, FETCH em um laço LOOP e CLOSE.
    • Dentro do laço, registra a alteração na tabela vendedores_auditoria para cada vendedor cujo salário atual seja menor que 2600.
  2. Chame CALL AtualizaSalarios() e confirme que os vendedores 1 e 2 foram registrados na auditoria (salário abaixo de 2600), mas o vendedor 3 não.
  3. Explique o papel do CONTINUE HANDLER FOR NOT FOUND nesse processo.

Bloco 4: Tratamento de exceções com SIGNAL

  1. Crie a procedure RegistraPromocao com IN id_vendedor INT, IN percentual DECIMAL(5,2). Dentro dela:
    • Declare um EXIT HANDLER FOR SQLEXCEPTION que executa ROLLBACK e dispara um erro customizado com SIGNAL SQLSTATE '45000'.
    • Valide que o percentual informado é maior que zero. Se não for, dispare o erro com a mensagem "Percentual inválido".
    • Se válido, aplique o aumento e confirme a transação com COMMIT.
  2. Chame CALL RegistraPromocao(3, 15) e confirme o aumento no salário de Fernanda.
  3. Chame CALL RegistraPromocao(3, -5) e observe que a operação é cancelada com a mensagem personalizada.
  4. Compare EXIT HANDLER e CONTINUE HANDLER: o que muda no fluxo do bloco em cada caso?

Orientações Finais

  • Delimitador: No MySQL, todo bloco de múltiplas linhas precisa ser criado entre DELIMITER $$ e DELIMITER ;.
  • Terminadores: Cada comando interno do bloco deve terminar com ponto e vírgula (;).
  • Cursores: Sempre feche o cursor com CLOSE antes do END para liberar recursos do servidor.
  • Validação: Confirme os efeitos (salários, contagens, auditoria) com um SELECT após cada CALL.
  • Tente sozinho: Resolva os blocos sem consultar a aula primeiro; volte a ela somente se travar em algum conceito.
