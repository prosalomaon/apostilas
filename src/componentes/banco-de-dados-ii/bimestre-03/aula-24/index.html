Teoria & Conceitos

1. O que é um Gatilho (Trigger)?

Um trigger é um objeto de banco de dados associado a uma tabela que é "disparado" (ativado) automaticamente quando ocorre uma instrução INSERT, UPDATE ou DELETE. Ele é utilizado para garantir que regras de negócio complexas sejam aplicadas de forma consistente, independentemente da aplicação que acessa os dados.

Principais Finalidades

  • Validação de Dados: Verificar ou rejeitar valores antes que entrem na tabela.
  • Auditoria e Log: Registrar em tabelas separadas quem alterou um dado e qual era o valor antigo.
  • Sincronização: Manter tabelas de resumo ou caches atualizados em tempo real.
  • Integridade Semântica: Implementar regras que o SGBD não suporta via restrições (constraints) estáticas.

Tipos de Disparo e Eventos

Os gatilhos são definidos por quando eles ocorrem e qual evento os ativa:

Quanto ao Momento (Timing)

  • BEFORE: Dispara antes da execução da operação. É ideal para validar dados ou modificar valores que estão sendo inseridos (ex: sanitização de strings).
  • AFTER: Dispara depois que a operação foi concluída com sucesso. É usado para tarefas que dependem da confirmação do dado, como logs de auditoria ou replicação.

Quanto à Abrangência

  • Row-Level (Por Linha): O gatilho executa uma vez para cada linha afetada pelo comando (ex: se um UPDATE altera 100 linhas, o gatilho roda 100 vezes).
  • Statement-Level (Por Instrução): O gatilho executa apenas uma vez para o comando inteiro, não importa quantas linhas foram afetadas (recurso comum no PostgreSQL).

Palavras-chave: NEW e OLD

Para manipular os dados dentro do gatilho, utilizamos as palavras-chave NEW e OLD:

  • NEW: Refere-se aos novos valores que estão sendo inseridos ou atualizados.
  • OLD: Refere-se aos valores antigos que existiam antes do UPDATE ou ao registro que está sendo removido no DELETE.

Implementação Prática

Exemplo no MySQL: Auditoria Simples

No MySQL, o trigger é criado diretamente sobre a tabela. O exemplo abaixo registra uma mensagem quando um novo produto é inserido: 

DELIMITER //

CREATE TRIGGER ai_produto_log
AFTER INSERT ON produto
FOR EACH ROW
BEGIN
    -- Insere um registro em uma tabela de log
    INSERT INTO log_atividades (descricao, data_hora)
    VALUES (CONCAT('Novo produto inserido: ', NEW.descricao_produto), NOW());
END //

DELIMITER ;

Exemplo no PostgreSQL: Trigger de Timestamp

No PostgreSQL, o processo é feito em duas etapas: primeiro cria-se uma Trigger Function (usando PL/pgSQL) e depois vincula-se essa função à tabela através do comando CREATE TRIGGER. 

-- 1. Criando a função do gatilho
CREATE OR REPLACE FUNCTION func_atualiza_timestamp()
RETURNS trigger AS $$
BEGIN
    NEW.ultima_atualizacao := CURRENT_TIMESTAMP; -- Modifica o registro antes de salvar
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2. Vinculando a função à tabela (Evento BEFORE)
CREATE TRIGGER tr_timestamp_vendedores
BEFORE UPDATE ON vendedores
FOR EACH ROW
EXECUTE PROCEDURE func_atualiza_timestamp();

Vantagens e Cuidados

Vantagens

  • Segurança: Impede que dados inválidos entrem no banco mesmo que o programador esqueça de validar no código PHP ou Java.

Cuidados

  • Performance: Gatilhos "pesados" (com muitas consultas internas) podem tornar as operações de escrita (INSERT/UPDATE) lentas, pois o banco precisa processar o gatilho antes de confirmar a transação.
  • Efeitos Colaterais: Um gatilho em uma tabela pode disparar outro gatilho em uma segunda tabela, criando uma "cascata" que pode ser difícil de depurar se não for bem planejada.

Dicas & Lembretes

  • Privilégios: Para criar gatilhos, o usuário precisa da permissão específica TRIGGER para aquela tabela.
  • Visões: Versões modernas do PostgreSQL (9.1+) permitem gatilhos do tipo INSTEAD OF em Views, permitindo que visões complexas se tornem atualizáveis.
  • Manutenção: Em métodos ágeis, lembre-se que ao refatorar tabelas, os gatilhos associados também precisam ser revisados e testados para manter a semântica do sistema.

Como aplicar na Prática

  • Auditoria de alterações: Use um trigger AFTER UPDATE que grava OLD.valor e NEW.valor em uma tabela de histórico, permitindo reconstruir o que mudou em cada registro.
  • Sanitização de entrada: No BEFORE INSERT, aplique TRIM() ou capitalização em colunas de texto antes do dado ser salvo.
  • Manutenção de resumos: Mantenha um contador de pedidos por vendedor atualizado em tempo real com triggers de inserção/exclusão em vez de recalcular tudo a cada consulta.
  • Validação de regras de negócio: Bloqueie operações inválidas (ex: saldo negativo, desconto acima do limite) com SIGNAL no MySQL ou RAISE EXCEPTION no PostgreSQL.
