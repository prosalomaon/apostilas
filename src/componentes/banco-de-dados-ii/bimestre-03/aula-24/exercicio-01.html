Enunciado

Você foi contratado(a) para garantir a integridade e a auditoria do banco de dados da loja TechLivre. As regras de negócio devem ser aplicadas diretamente no servidor, através de gatilhos (triggers), independentemente da aplicação que acessa os dados.

Seu objetivo é criar gatilhos no MySQL (e alguns no PostgreSQL) que validam dados, mantêm timestamps atualizados e registram auditoria das alterações.

Preparação

  1. Ambiente: Abra seu terminal ou o MySQL Workbench e conecte-se ao seu servidor local.
  2. Script: Execute o script da seção "1. Script de Preparação" integralmente.
  3. Resolução: Crie cada gatilho com DELIMITER // e DELIMITER ; ao final.
  4. Validação: Após cada gatilho, execute operações de escrita e consulte as tabelas de auditoria para confirmar o comportamento esperado.

1. Script de Preparação (MySQL)

Execute o script abaixo para criar o banco, as tabelas e a massa de dados do cenário:

CREATE DATABASE techlivre_db;
USE techlivre_db;

CREATE TABLE produto (
    codigo INT AUTO_INCREMENT PRIMARY KEY,
    descricao_produto VARCHAR(150) NOT NULL,
    preco_venda DECIMAL(10,2) NOT NULL,
    saldo_estoque INT NOT NULL DEFAULT 0,
    ultima_atualizacao DATETIME
);

CREATE TABLE log_atividades (
    id_log INT AUTO_INCREMENT PRIMARY KEY,
    descricao VARCHAR(255),
    data_hora DATETIME DEFAULT NOW()
);

CREATE TABLE auditoria_produto (
    id_auditoria INT AUTO_INCREMENT PRIMARY KEY,
    codigo_produto INT,
    operacao VARCHAR(10),
    valor_antigo TEXT,
    valor_novo TEXT,
    usuario VARCHAR(100),
    data_hora DATETIME DEFAULT NOW()
);

INSERT INTO produto (descricao_produto, preco_venda, saldo_estoque) VALUES
('Notebook', 2999.90, 10),
('Monitor', 899.90, 15),
('Teclado', 149.90, 30);

2. Desafios de Prática

Bloco 1: Gatilho de auditoria AFTER INSERT (MySQL)

  1. Crie o gatilho ai_produto_log que, após a inserção de um produto, registra uma mensagem na tabela log_atividades contendo o texto CONCAT('Novo produto inserido: ', NEW.descricao_produto) e a data/hora atual.
  2. Teste inserindo um novo produto (ex: "Mouse") e confirme que o log foi criado.
  3. Por que esse gatilho foi criado como AFTER INSERT e não BEFORE INSERT?

Bloco 2: Gatilho de timestamp BEFORE UPDATE (MySQL)

  1. Crie o gatilho bu_produto_timestamp que, antes de uma atualização em produto, define NEW.ultima_atualizacao com o NOW().
  2. Atualize o preço do produto de código 2 e confirme que a coluna ultima_atualizacao foi preenchida automaticamente.
  3. Explique a função da palavra-chave NEW nesse gatilho.

Bloco 3: Auditoria com OLD e NEW (MySQL)

  1. Crie o gatilho au_produto_auditoria que, após um UPDATE em produto, insere na tabela auditoria_produto:
    • o código do produto;
    • a operação 'UPDATE';
    • o valor antigo (CONCAT(OLD.codigo, ' - ', OLD.descricao_produto));
    • o valor novo (CONCAT(NEW.codigo, ' - ', NEW.descricao_produto));
    • o usuário (CURRENT_USER()).
  2. Atualize o saldo em estoque do produto 3 e confirme o registro de auditoria.
  3. No evento INSERT, por que OLD não está disponível?

Bloco 4: Gatilho de validação BEFORE INSERT (MySQL)

  1. Crie o gatilho bi_produto_valida que, antes da inserção de um produto, rejeita (com SIGNAL SQLSTATE '45000') as inserções em que o preco_venda seja menor ou igual a zero.
  2. Teste inserindo um produto com preço inválido (ex: 0.00) e confirme que a operação é cancelada com a mensagem personalizada.
  3. Compare esse comportamento com o de uma restrição CHECK: quando faz sentido preferir o gatilho?

3. Desafio Extra (PostgreSQL)

Se tiver acesso a um PostgreSQL, adapte o gatilho de timestamp em duas etapas:

  1. Crie a função de gatilho func_atualiza_timestamp() que define NEW.ultima_atualizacao := CURRENT_TIMESTAMP e retorna NEW.
  2. Vincule a função à tabela com CREATE TRIGGER tr_timestamp_vendedores BEFORE UPDATE ON vendedores FOR EACH ROW EXECUTE PROCEDURE func_atualiza_timestamp();.
  3. Explique por que no PostgreSQL o processo é dividido entre função de gatilho e comando CREATE TRIGGER.

Orientações Finais

  • Momento: Use BEFORE para validar ou modificar valores antes da gravação e AFTER para tarefas dependentes da confirmação (auditoria/log).
  • NEW e OLD: NEW existe em INSERT/UPDATE; OLD existe em UPDATE/DELETE.
  • Performance: Evite consultas pesadas dentro do gatilho; elas tornam as escritas lentas.
  • Cascata: Lembre-se de que um gatilho pode disparar outro gatilho em cascata.
  • Tente sozinho: Resolva os blocos sem consultar a aula primeiro; volte a ela somente se travar em algum conceito.
