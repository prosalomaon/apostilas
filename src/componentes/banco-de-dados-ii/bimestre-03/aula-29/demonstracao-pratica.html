Cenário: Sistema de Vendas "TechStore"

Esta demonstração pratica todos os conceitos do terceiro bimestre em um único sistema integrado de vendas de uma loja de tecnologia: blocos SQL, Stored Procedures (com transação, tratamento de exceções e cursores), Stored Functions, Triggers, além de relembrar transações e consultas avançadas.

Copie e execute cada bloco de código na ordem apresentada no MySQL Workbench ou terminal. Ao final, você terá 1 banco, 1 function, 2 procedures (uma com transação + exceções e outra com cursor), 1 trigger e 1 consulta de consolidação funcionando.

Etapa 1: Criação do Banco e das Tabelas

Começamos recriando o esquema base, relembrando DDL, constraints e integridade referencial já vistos em bimestres anteriores. 

-- 1. Criar o banco
CREATE DATABASE IF NOT EXISTS techstore_revisao;
USE techstore_revisao;

-- 2. Tabela de vendedores
CREATE TABLE vendedores (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    meta_mensal DECIMAL(10,2) NOT NULL DEFAULT 0.00
);

-- 3. Tabela de produtos
CREATE TABLE produtos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(120) NOT NULL,
    preco DECIMAL(10,2) NOT NULL,
    estoque INT NOT NULL DEFAULT 0
);

-- 4. Tabela de pedidos (integridade referencial)
CREATE TABLE pedidos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    id_vendedor INT NOT NULL,
    id_produto INT NOT NULL,
    data_pedido DATE NOT NULL,
    valor_total DECIMAL(10,2) NOT NULL,
    status ENUM('PENDENTE', 'PAGO', 'CANCELADO') DEFAULT 'PENDENTE',
    FOREIGN KEY (id_vendedor) REFERENCES vendedores(id),
    FOREIGN KEY (id_produto) REFERENCES produtos(id)
);

-- 5. Tabela de auditoria (usada pelo trigger)
CREATE TABLE auditoria_pedidos (
    id INT PRIMARY KEY AUTO_INCREMENT,
    acao VARCHAR(10) NOT NULL,
    id_pedido INT,
    data_log DATETIME DEFAULT NOW()
);

Etapa 2: Stored Function para Cálculo

Criamos uma function para calcular o imposto sobre um valor. Funções podem ser usadas dentro de consultas SQL. 

DELIMITER //

CREATE FUNCTION CalcularImposto(valor DECIMAL(10,2)) RETURNS DECIMAL(10,2)
DETERMINISTIC
BEGIN
    RETURN valor * 0.18; -- 18% de imposto
END //

DELIMITER ;

-- Teste: função dentro de um SELECT
SELECT CalcularImposto(1000.00) AS imposto; -- 180.00

Etapa 3: Stored Procedure com Transação e Exceções

Esta procedure consolida procedure + transação + tratamento de exceções. Ela registra um pedido, dá baixa no estoque e — se qualquer passo falhar — faz ROLLBACK e lança um erro customizado com SIGNAL. 

DELIMITER //

CREATE PROCEDURE RegistrarPedido(
    IN p_vendedor INT,
    IN p_produto INT,
    IN p_quantidade INT
)
BEGIN
    DECLARE v_preco DECIMAL(10,2);
    DECLARE v_estoque INT;
    DECLARE v_total DECIMAL(10,2);

    -- Tratamento de exceções: qualquer erro desfaz a transação
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Erro ao registrar pedido - rollback executado';
    END;

    START TRANSACTION;

    -- Validação de regra de negócio com SIGNAL
    IF v_quantidade <= 0 THEN
        SIGNAL SQLSTATE '22000' SET MESSAGE_TEXT = 'Quantidade deve ser maior que zero';
    END IF;

    SELECT preco, estoque INTO v_preco, v_estoque
    FROM produtos WHERE id = p_produto
    FOR UPDATE;

    IF v_estoque < v_quantidade THEN
        SIGNAL SQLSTATE '22000' SET MESSAGE_TEXT = 'Estoque insuficiente';
    END IF;

    SET v_total = v_preco * v_quantidade;

    INSERT INTO pedidos (id_vendedor, id_produto, data_pedido, valor_total, status)
    VALUES (p_vendedor, p_produto, CURDATE(), v_total, 'PENDENTE');

    -- Baixa no estoque (atualização com segurança)
    UPDATE produtos SET estoque = estoque - v_quantidade WHERE id = p_produto;

    COMMIT;
END //

DELIMITER ;

Etapa 4: Stored Procedure com Cursor

Esta procedure percorre linha por linha os pedidos pendentes com um cursor e aplica uma regra de negócio para cada um. Observe a ordem correta das declarações: variáveis → cursor → HANDLER. O CONTINUE HANDLER FOR NOT FOUND é o que encerra o loop quando as linhas acabam. 

DELIMITER //

CREATE PROCEDURE ProcessarPedidosPendentes()
BEGIN
    -- 1. Variáveis locais
    DECLARE v_id INT;
    DECLARE v_total DECIMAL(10,2);
    DECLARE fim_cursor BOOLEAN DEFAULT FALSE;

    -- 2. Cursor: percorre os pedidos pendentes
    DECLARE cur_pedidos CURSOR FOR
        SELECT id, valor_total FROM pedidos WHERE status = 'PENDENTE';

    -- 3. Handler: quando não houver mais linhas, encerra o loop
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET fim_cursor = TRUE;

    OPEN cur_pedidos;

    processa: LOOP
        FETCH cur_pedidos INTO v_id, v_total;

        IF fim_cursor THEN
            LEAVE processa;
        END IF;

        -- Regra de negócio: pedidos acima de R$ 1.000,00 tornam-se PAGO
        IF v_total >= 1000.00 THEN
            UPDATE pedidos SET status = 'PAGO' WHERE id = v_id;
        END IF;
    END LOOP processa;

    CLOSE cur_pedidos;
END //

DELIMITER ;

CALL ProcessarPedidosPendentes();

Cursor dentro da demonstração

O cursor é usado quando uma consulta precisa ser processada linha a linha. Sem o CONTINUE HANDLER FOR NOT FOUND, o FETCH depois da última linha dispararia um erro (código 02000).

Etapa 5: Trigger de Auditoria

Um trigger que registra automaticamente na auditoria sempre que um pedido for inserido (AFTER INSERT). Ele usa NEW para acessar a nova linha. 

DELIMITER //

CREATE TRIGGER trg_auditoria_insercao
AFTER INSERT ON pedidos
FOR EACH ROW
BEGIN
    INSERT INTO auditoria_pedidos (acao, id_pedido)
    VALUES ('INSERT', NEW.id);
END //

DELIMITER ;

Etapa 7: Consulta de Consolidação (DQL Avançada)

Uma consulta que consolida o desempenho dos vendedores usando JOIN, agregação, GROUP BY, HAVING e a function criada. 

SELECT
    v.nome AS vendedor,
    COUNT(p.id) AS total_pedidos,
    SUM(p.valor_total) AS faturamento,
    CalcularImposto(SUM(p.valor_total)) AS imposto_estimado
FROM vendedores v
LEFT JOIN pedidos p ON p.id_vendedor = v.id
WHERE p.status != 'CANCELADO' OR p.status IS NULL
GROUP BY v.nome
HAVING SUM(p.valor_total) > 1000.00
ORDER BY faturamento DESC;

-- Verificar a auditoria preenchida pelo trigger

Dicas & Lembretes

  • DELIMITER: Sempre use DELIMITER // antes de criar procedures, functions e triggers de múltiplas linhas no MySQL.
  • Transação + Handler: combine START TRANSACTION com EXIT HANDLER FOR SQLEXCEPTION e ROLLBACK para garantir atomicidade. Lembre-se: o DECLARE HANDLER deve vir após as variáveis e antes de qualquer comando executável (inclusive o START TRANSACTION) — posição errada gera erro de sintaxe.
  • FOR UPDATE: o SELECT ... FOR UPDATE bloqueia a linha para evitar problemas de concorrência dentro da transação.
  • SIGNAL: use SIGNAL SQLSTATE '22000'/'23000' para validar regras de negócio que as constraints não alcançam.
  • Cursor: para percorrer linha a linha um resultado, use o ciclo OPEN → FETCH (em um LOOP) → CLOSE, sempre com um CONTINUE HANDLER FOR NOT FOUND para encerrar o loop ao fim das linhas.
  • Trigger NEW/OLD: NEW é a linha nova; use em AFTER INSERT/UPDATE.
  • Recompilação: ao alterar um objeto, use DROP ... IF EXISTS antes do CREATE.
