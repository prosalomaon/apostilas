Enunciado

Uma startup de tecnologia chamada DevRapid desenvolveu um sistema de controle de pedidos ao longo de dois anos. Com a pressão constante por novas funcionalidades, a equipe nunca reservou tempo para refatoração. Agora, adicionar uma nova feature que deveria levar 1 dia está levando mais de uma semana, e os bugs em produção aumentaram 300% no último trimestre.

Você foi contratado como consultor de qualidade de software e recebeu os seguintes relatos da equipe. Leia cada situação e responda as questões a seguir.

Situações Relatadas

  1. Situação A: O desenvolvedor sênior João é o único que entende o módulo de faturamento. Ele está de férias e ninguém consegue corrigir um bug crítico que surgiu neste módulo.
  2. Situação B: A equipe de gestão decidiu, há seis meses, lançar uma versão do produto sem validação de dados nas entradas do formulário para cumprir um prazo contratual. Eles registraram a decisão em ata e criaram tarefas no backlog para corrigir isso na próxima sprint.
  3. Situação C: Um desenvolvedor júnior criou um módulo de pagamento onde todas as funções têm nomes como f1(), proc(x,y) e calc2(a). Ele nunca estudou sobre Clean Code ou boas práticas de nomenclatura.
  4. Situação D: Após desenvolver o sistema de autenticação, a equipe percebeu que deveria ter utilizado um padrão de projeto Strategy para gerenciar os diferentes provedores de login (Google, Facebook, GitHub). A implementação atual funciona, mas é muito difícil adicionar um novo provedor.

Questões

  1. Classificação nos Quadrantes: Identifique em qual dos quatro quadrantes de Martin Fowler se enquadra a dívida técnica gerada em cada uma das Situações A, B, C e D. Justifique cada resposta com base nas dimensões de intencionalidade (Deliberado/Inadvertido) e prudência (Prudente/Imprudente).
  2. Consequências: Quais são as consequências práticas observadas na DevRapid que indicam acúmulo de dívida técnica? Cite pelo menos três e relacione cada uma aos conceitos estudados na aula.
  3. Plano de Ação: Elabore um plano de ação com pelo menos três medidas concretas que a DevRapid deveria adotar para começar a reduzir sua dívida técnica. Para cada medida, indique qual ferramenta ou prática do conteúdo da aula seria aplicada.
  4. Análise do Código: O trecho abaixo foi encontrado no sistema da DevRapid. Identifique os problemas de qualidade de código e reescreva-o aplicando os princípios do Clean Code. 
    // Código encontrado no sistema
function p(d, v, c) {
  var r;
  if (c == 1) {
    r = v * 0.05;
  } else if (c == 2) {
    r = v * 0.10;
  } else {
    r = 0;
  }
  return v - r;
}

Orientações

  • Leia o enunciado com atenção e revise o conteúdo da aula antes de responder.
  • Para a questão 1, lembre-se que os quadrantes combinam duas dimensões simultaneamente.
  • Para a questão 4, foque em: nomes de variáveis e funções, uso de constantes nomeadas e clareza de intenção.
  • Entregue a atividade no prazo estipulado pelo professor.
